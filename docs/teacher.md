# 老师手册

老师负责课程、学生名单、讲次与批改、考试成绩与教案。所有功能都在登录后的导航栏入口。

结构是「课程 → 讲次 / 考试」：一个课程下可以有若干讲次（每次作业即一讲）和若干场考试。

| 层级 | 是什么 | 能做什么 |
|------|--------|----------|
| 课程 | 一学期的一门课 | 管学生名单、讲次、考试、教案与提示词 |
| 讲次 | 一次作业 / 一讲内容 | 上传教师版标准答案、收学生提交、AI 批阅与人工复核、发布批改报告 |
| 考试 | 一张卷 | 只录入分数与评语，不上传试卷、不做 AI 批阅 |

## 快速上手：30 分钟走完主流程

新账号第一次使用，按下面的顺序做一遍，就能把所有主要流程都过一遍（每一步都能在后面的章节里查到细节）：

1. **登录改密**：用管理员给的账号登录，初始密码 `123456` 时会被强制改密（见「登录与修改密码」）
2. **建课**：导航栏「我的课程」→ 填课程名称与简介 → 创建（见「创建课程」）
3. **加学生**：进入课程页 →「学生名单」卡片下拉选学生 →「加入课程」（见「添加学生到课程」）
4. **配 AI**：导航栏「AI 设置」→ 填接口地址、API Key、多模态模型 →「测试连接」→「使用此 Key」（见「AI 设置」）
5. **建讲次**：课程页「讲次」卡片 → 新建讲次，填标题（如 `01_绪论`）、说明、截止时间，上传**学生版讲义 PDF** 与**教师版标准答案 PDF**（见「新建讲次与上传讲义」）
6. **划范围**：讲次页「作业范围」→ 勾选教师版页码 →「保存并生成题目列表」→ 勾选本讲实际布置的题 → 保存（见「设置作业范围」）
7. **收作业**：学生自己上传，或老师点「代学生上传」批量补交（见「代学生上传作业」）
8. **批阅**：讲次页「提交与批阅」卡片点「AI 批阅」，任务进入后台队列（见「批阅方式」）
9. **复核**：点「逐题核对」，逐题改 OCR / 判定 / 评语并点「标记已复核」（见「人工复核」）
10. **发报告**：全部复核后点「生成批阅报告」→ 检查 Markdown →「发布给学生」（见「批改报告怎么发布给学生」）
11. **考试、教案、备份**：课程页的「考试」「教案」「课程备份」三张卡片（见对应章节）

卡在某一步时，可以打开页面右下角的「教学助手」直接问操作步骤；也可以在 Trae / Claude Desktop 里通过 MCP 检索这本手册。

## 登录与修改密码

- 账号由管理员创建；初始密码为 `123456` 时，首次登录必须先改密
- 右上角姓名可进入改密页；忘记密码只能找管理员重置
- 登录后默认进入「我的课程」

## 创建课程（建课、改课名、删除课程）

建课：「我的课程」→ 填写课程名称与简介 → 创建。课程卡片显示学生数、讲次数与考试数。创建者进入课程页后可点「编辑课程」修改课程名称与简介。

只有课程创建者能删除课程；共同管理老师不能删课。删除课程会连同该课程的讲次、考试、提交与教案一起删除，操作前建议先导出课程备份。

## 添加学生到课程（把学生加进课程、名单导入）

把学生加进课程：进入课程页，在「学生名单」卡片里从下拉中选择学生 → 「加入课程」。

- 下拉只列出管理员已创建、**处于启用状态**且尚未加入本课程的学生账号
- 建号由管理员负责；老师端不建号，也不再提供课程内的 CSV 批量导入
- 批量加很多人时，请管理员在「用户管理 → 批量创建」用姓名 CSV 建号，再回这里逐个加入

## 移出学生

名单每一行最右侧是「移出」按钮，点击后需在弹窗里二次确认。

⚠️ 移出是**数据库层面的永久删除**：该学生在本课程内的全部讲次提交、逐题批改结果、考试成绩与选课关系都会被删除，无法恢复。学生的账号与其它课程的数据不受影响。若只是想让其不再登录，请让管理员「停用」账号。

## 多名老师共同管理同一课程

课程页顶部「共同管理老师」卡片展示本课程的所有老师：

- **创建者**：建课的人，可以编辑课程名称与简介、添加 / 移除其它老师，也只有他能删除课程
- **共同管理**：可进入课程、管理学生名单、建改讲次与考试、批阅与发布报告，但不能编辑课程信息或增删老师
- 添加方式：点「＋ 添加老师」，从老师账号下拉中选择（只列出尚未加入本课程的老师）
- 移除后对方账号与其它课程不受影响；「我的课程」列表会显示「N 位老师共同管理」

## 新建讲次与上传讲义

课程页「讲次」卡片：填写标题（如「01_绪论」，讲次按标题升序排列）、说明、截止时间，可同时上传**学生版讲义 PDF**（发给学生的原卷，学生端可预览）与**教师版标准答案 PDF**（AI 批阅时作参考），两份都可稍后补传。一个课程可以有任意多个讲次。

- 学生版讲义 = 学生看到的卷子；教师版标准答案 = AI 批阅的对照材料，两者不要传反
- 没上传学生版讲义，学生仍可提交作业，但看不到原卷预览
- 没上传教师版标准答案，AI 批阅和自动批阅都不会执行

## 编辑讲次与截止时间

讲次页底部「讲次信息」可改标题、说明与截止时间，保存即生效；清空截止时间再保存即取消截止限制。课程页讲次表格里会显示该讲有无「学生版 / 教师版」文件。

讲次页「标准答案（教师版）」卡片支持上传或更换答案 PDF；上方「学生版讲义」卡片用于上传发给学生的原卷。AI 批改以教师版 PDF 为参考。

## 代学生上传作业

讲次页「提交与批阅」卡片右上角「代学生上传」：选择学生后，可一次选择多张图片 / PDF，或在手机上直接拍照。文件先进入**草稿箱**，可预览缩略图、逐个删除，点「确认上传」才真正写入。

- 同一批多图记为**一次提交**，列表显示 `查看扫描件 1/3`、`2/3`，AI 批阅会按顺序合并
- 单文件 ≤20MB，一次最多 20 个文件
- 需要更正时直接再传一次即可，**以最新一次提交为准**

## 设置作业范围（只批改布置的题目）

上传教师版标准答案后即可使用「作业范围」卡片。AI 批阅本身也依赖教师版答案，因此标准流程是先上传答案、再划定范围：

1. 在「教师版页码」勾选本讲实际对应的答案页（这一步与生成题目清单合并，不再需要单独分析按钮）
2. 点「保存并生成题目列表」，AI 用选中的答案页列出题号、满分与考查内容（约 20~60 秒）
3. 勾选本讲实际布置的题目（可「全选 / 全不选」），保存；保存时会顺带为勾选的题目生成知识点标签
4. 之后每份作业的 AI 批阅只处理勾选的题目，未勾选的题目不会出现在批阅结果里

必须至少勾选一道题并保存，AI 批阅才会执行；没有教师版答案或没有划定范围时，即使学生已经提交作业，批阅按钮也不可用。换答案或换页码时重新勾选并点「保存并生成题目列表」即可刷新清单（会提示确认覆盖）。

## 教师版页码怎么勾选（只发送相关页）

「作业范围」卡片里还有一块「教师版页码」：系统把教师版 PDF 逐页渲染成缩略图，勾选本讲作业实际对应的页。

- 学生交的是 PDF 的第几页，这里就勾第几页；批阅时只把这些页发给模型
- 支持按打印习惯填范围：`1-5, 8, 10-12`，点「按范围勾选」自动对应缩略图
- 也提供「全选 / 全不选」；**全不选并保存 = 发送整份答案**
- 点「保存并生成题目列表」会同时保存页码并立即生成题目清单，不需要再点其他按钮；未保存页码或全不选时分析、批阅整份答案
- 更换教师版 PDF 会自动清空已选页码（页数可能变了），需要重新勾选

按一份 26 页学生卷 + 20 页答案算，答案只勾 4 页可把发给模型的图片从 46 张降到 30 张，输入 token 减少约三成。

## 知识点标签与薄弱点分析

保存作业范围时，系统会顺带调用一次 AI，为勾选的每道题生成 1~4 个知识点标签（如「氧化还原反应」「离子方程式」），保存在数据库的 `question_tags` 表中，并显示在「作业范围」表格的「知识点标签」列。标签生成失败不会影响范围保存，可点「重新生成知识点标签」重试。

标签用于两种分析（都需先完成该讲作业的 AI 批阅）：

- **横向（同一讲、全班）**：讲次页「知识点分析（全班）」→「分析知识点」。系统把每道题题号、关联知识点、全班错误率与典型错误评语交给 AI，找出同学们普遍薄弱的知识点，并给出讲评课的教学建议（整体掌握情况、高风险知识点、讲评课建议）。
- **纵向（同一学生、跨讲次）**：学生详情页「纵向知识点分析」→「分析薄弱点」。系统汇总该生各知识模块的累计掌握度、跨讲次趋势、反复出现的作答习惯问题，按标签找反复出现的薄弱点，并给出「先补前置基础、再练综合应用」的行动方案。

两类分析都有系统内置默认提示词，也可复制成自己的副本修改，再到课程页「提示词配置」选择本课程使用哪一条，详见下文「我的提示词」。

每次分析都会新增一条记录并保留上一次结果；在「AI 消耗记录」中对应「知识点标注」「横向知识点分析」「纵向知识点分析」。标签与批改题号按前导数字匹配，更换答案或作业范围后重新保存一次即可刷新。

## 学科知识图谱（上传资料冷启动）

导航栏「知识图谱」按学科沉淀概念与前置关系，资料上传后自动抽取，后续可继续追加，不需要一次性准备齐全。

- **新建图谱**：填写学科（如「高中化学」）、图谱名称，可选学段与说明。图谱按学科共享：所有老师可查看，创建者与管理员可上传资料或删除。
- **上传资料**：支持 PDF / Markdown / TXT，可一次多选。系统按页抽取文字并切块，逐批交给 AI 抽取概念、定义、别名，以及「前置 / 包含 / 相关」三类关系；带依据与置信度。
- **增量合并**：新增资料只合并差异，同名或别名概念会归并到同一节点，关系去重；相同内容的文件按文件指纹自动跳过，不会重复消耗 AI。
- **状态查看**：资料状态为「待建图 / 建图中 / 完成 / 失败」，建图期间页面会自动刷新；失败原因（如扫描版 PDF 没有文字层）会显示在资料下方。单份资料最多取前 12 万字用于建图。
- **出处回收**：删除某份资料时，只移除仅由它支撑的概念与关系；仍被其他资料引用的节点会保留。
- **备份与迁移**：原始资料保存在 `uploads/kg/<图谱ID>/`，节点、关系与文本块保存在数据库；都会进入系统备份包，灾备或整体迁移时一并带走。

当前版本先完成「资料 → 图谱」的沉淀；课程关联图谱与根因分析接入会在后续版本中接上，届时纵向分析里的「前置薄弱链」将直接来自这里。

## 查看单个学生的进度

课程页学生名单里点姓名（或「进度」）进入学生详情：上方是该生在本课程每一讲次的提交次数、状态与正确率（可直达批阅页），下方是该生所有考试的得分与评语。学生资料（姓名 / 学籍号）与登录密码由管理员统一维护，老师端只读。

## 批阅方式（整份原卷，不切题）

讲次页不需要「提取标准答案」；但必须先上传教师版答案并划定作业范围，未上传答案或未划定范围时批阅不会执行。点提交卡片上的「AI 批阅」时，系统会把两份材料一起交给模型：

1. 学生提交的作业（PDF 或扫描图片）
2. 作业的教师版标准答案 PDF

系统把两份文件的每一页渲染成图片后一次性发送，模型看到完整原卷，逐题输出题号、学生作答 OCR、标准答案要点、判定、建议分数与评语，不做任何题目裁剪。需要「AI 设置」里选择**支持图片输入**的多模态模型，输出上限建议 ≥32k。

单份批阅实测：约 26 页图片、45 题，DeepSeek 视觉版约 90 秒、4.5 万 token；模型卡死时 5 分钟超时后直接报错，不会反复重试。

## 后台批阅、自动批阅与批阅失败

**后台批阅**：点「AI 批阅」后任务进入后台队列，页面立即返回并显示「排队中 / 批阅中」。可以继续给其他学生提交批阅，也可以关闭浏览器或离开页面，任务会继续执行并把结果写入数据库；回到讲次页即可看到「重新批阅」和最新结果。默认同时处理 2 份，避免触发模型限流，可通过环境变量 `GRADING_CONCURRENCY` 调整（1~4）。服务重启时未完成的任务会被标记为失败并提示重新提交。有任务在后台运行时，教师页顶部会显示「后台批改中」和数量，鼠标悬停（手机上点按）可查看队列里每份作业的学生、讲次以及「待批改 / 批改中」状态，点击条目可直接回到对应讲次。

**自动批阅**：系统每 6 小时检查一次，把「已提交」且从未批阅过的作业自动送入后台队列。只有讲次已经上传教师版答案 PDF、并划定了作业范围时才会触发；没有上传答案的讲次不会自动批阅。演示模式、未配置 AI API Key、以及开启「仅闲时批阅」但当前处于高峰时段的老师会被跳过。可通过环境变量 `AUTO_GRADE=0` 关闭，或用 `AUTO_GRADE_HOURS` 调整检查间隔（默认 6 小时）。

**批阅失败怎么办**：先看讲次页的失败提示与「AI 消耗记录」，再到「AI 设置」点该配置行的「测试连接」，确认 Key 有效、额度充足、模型支持图片输入；改好后在提交列表点「重新批阅」。常见原因与处理见文末「常见问题」。

## AI 设置

导航栏「AI 设置」：

| 项 | 说明 |
|----|------|
| 当前状态 | 已配置时显示「当前 AI API 已配置」、正在使用的名称、基地址、掩码 Key 与模型 |
| 多组配置 | 可保存多套互相独立的配置（如阿里云一套、腾讯云两套），每套分别保存基地址、Key 和模型 |
| 切换 | 列表里点「使用此 Key」切换当前生效的一套，切换后模型与基地址一起恢复 |
| 接口地址 | 任意 OpenAI 兼容服务，如 `https://tokenhub.tencentmaas.com/v1` |
| API Key | 新增时必填；页面只展示首尾字符，删除当前 Key 后会自动切换到最近保存的一组 |
| 模型 | 在配置列表中每行单独填写并保存；必须是**支持图片输入的多模态模型**，如 `deepseek-v4.1-flash`（腾讯云 TokenHub 推荐）、`glm-5.3-flash`、`gpt-4o` |
| 演示模式 | 未配 Key 时可用，生成占位批阅结果，仅用于走通流程 |
| 测试连接 | 每行都有独立的「测试连接」，只使用该行的地址、Key 与模型，不受当前选中项影响 |

「AI API 配置」位于页面最上方、模型参考与批阅设置之前；切换 Key 后模型清单会按新的基地址重新识别。

模型不再有全局下拉框，而是跟随每套配置保存，切换配置时自动恢复对应模型。服务端若通过环境变量注入了 `AI_API_KEY`，Key 由部署方接管，页面上的管理不生效；只注入 `AI_API_URL` 时仍可正常保存多套配置，保存的配置优先。

## AI 消耗记录

想问「AI 花了多少钱」「这次批阅用掉多少 token」，看这里的「AI 消耗记录」。讲次详情、逐题核对和教师版批改报告页面底部会显示「AI 消耗记录」，用于查看作业范围分析、作业批阅、讲次汇总、自动生成报告评价和重新生成总评的消耗。

- 每次点击都会生成一条新的操作记录；重新分析、重新批阅和重新生成不会覆盖旧记录，失败的操作也会保留
- 每次记录展示输入、输出、合计 token、整体耗时和预估费用；发生自动重试时，各次请求分别保存，页面展示合计值与请求次数
- token 来自服务商返回的 `usage`，数据库同时保存可获得的缓存 token 与推理 token；服务商未返回时显示「未知」，不会按 0 计算
- 费用按操作开始时的模型输入价、输出价和高峰倍率快照估算，仅供成本参考，实际费用以服务商账单为准；缺少 token 或模型价格时费用显示「未知」
- 演示模式不产生真实消耗记录；仅在本地重排报告、没有调用 AI 时也不记录。数字助手和「测试连接」暂未纳入此记录

## 我的提示词（批改 / 报告 / 知识点分析）

导航栏「我的提示词」按四类管理提示词：批改、报告、横向分析、纵向分析。

- 每类系统内置一条默认提示词，全局可用、不可删除、不可修改；代码升级时内容会自动更新。
- 点「复制为我的提示词」得到可自由修改的副本，改到满意后在课程页选用。
- 自建提示词可命名、修改、复制多份做对比测试、删除；删除后引用它的课程自动回落到系统默认。
- 只需写角色、规则与要求，JSON 输出格式由系统自动追加，保证结果能被解析。
- 两类分析提示词用占位符引用输入数据，保留占位符即可按讲次 / 学生自动填充；新建弹窗与每条提示词上方都会列出可用占位符：
  - 横向：`{subject_and_course}`、`{lecture_name}`、`{total_students}`、`{aggregated_question_stats}`
  - 纵向：`{lecture_count}`、`{subject_and_course}`、`{student_name}`、`{lecture_range}`、`{module_mastery_stats}`、`{kg_weakness_chains}`、`{error_habit_stats}`、`{trend_data}`
  - 自定义时若删掉部分占位符，系统仍会把未注入的数据附在提示词末尾，不会让模型「无数据可依」。

课程页「提示词配置」为本课程分别选择批改、报告、横向分析、纵向分析提示词；不选即用系统默认。
共同管理该课程的其他老师自建的提示词也会出现在下拉里。

## 人工复核（怎么复核、逐题核对）

复核就是逐题核对：AI 批阅完成后，老师在复核页逐题确认，复核结果保存后立即对学生发布。

讲次页的提交列表，每份提交有两个入口：

- **AI 批阅 / 重新批阅**：把学生作业与标准答案整份交给模型，一次返回逐题结果
- **逐题核对**：打开发布前的复核页

复核页两栏同屏：

| 左 | 右 |
|----|----|
| 可编辑的 OCR 文本框、判定、评语 | 该题标准答案（可修正） |

- 复核时每题有判定下拉：对 / 半对 / 错 / 无法判定；可修改评语
- 复核只按判定统计，作业不单独赋分：页面底部显示正确率（完全答对题数 ÷ 已判定题数）
- 点保存后，提交状态变为「已批改」，复核结果学生端立即可见；**保存即发布**
- 页面右上角「查看原始扫描件」可并排打开学生原卷 PDF 核对

逐题核对页保存后即为最终结果，总分与评语在该页统一修改。

## 批改报告怎么发布给学生

AI 批阅完成后会自动生成一份 Markdown 批改报告（逐题明细表、失分点归因、评价），可在讲次页「批改报告」进入查看。

复核与发布的顺序：

1. 打开「逐题核对」页，题目默认全部折叠，折叠时标题栏就显示「待复核 / ✓ 已复核」
2. 逐题点开核对，改完点「标记已复核」；右上角显示「已复核 x/N 题」
3. 全部复核完成后，「总评」下方的「生成新的总评」才可用；点它会按本次逐题结果让 AI 重写总评并回填到文本框，可继续手工修改
4. 全部题目都「已复核」后，「生成批阅报告」按钮才可点击；未复核完时按钮呈禁用样式，点击会弹窗提示还需审核多少题
5. 点「生成批阅报告」保存当前结果并跳到报告页；报告页的「编辑报告内容（Markdown）」可直接改源文并保存
6. 确认无误后点「发布给学生」，学生在「我的学习 → 讲次」里能看到逐题明细与报告；点「撤回发布」即收回

其他说明：

- 报告默认是草稿，学生看不到；逐题明细同样要等老师保存复核结果或发布报告后才公开
- 逐题核对保存时会按最新结果刷新报告表格与统计，评价段落沿用上次生成的内容
- 「重新生成」会重新调用模型写评价；「下载 .md」可导出源文件
- 报告包含：每个学生的逐题判定（✅/⚠️/❌）、统计行、失分点归因表，以及「做得好的地方 / 需要改的几处 / 下一步建议」

## 课程备份

课程页「课程备份」卡片点「导出课程备份」，会把整个课程打包成 zip 直接下载。只有本课程的老师（创建者与共同管理老师）能导出，其他老师与学生无权访问。

压缩包按「课程 → 讲次 → 学生」整理：

```text
课程名/
  讲次名/
    教案-学生版.pdf
    教案-教师版.pdf
    学生用户名/
      批改报告.md
      提交作业/
        原始作业文件.pdf
```

- 教案取讲次页上传的学生版讲义与教师版答案；未上传的一侧不会出现在包内
- 每个学生一个文件夹，使用登录用户名；多次提交会合并到「提交作业」，重名文件自动加序号
- 批改报告取该生最新一次已生成的报告；尚未批阅的学生不会生成报告文件
- 同名讲次会自动追加序号（如「第1讲 极限 (2)」）避免互相覆盖
- 生成后直接下载，同时服务器保留 1 天，期间可在卡片下方再次下载；过期自动清理

## 考试与成绩录入

课程页「考试」卡片可新建考试（名称、日期、满分、说明）；考试只记分数，不上传试卷、不走 AI 批阅。

点考试进入录分页：按学生逐个填写分数与评语，留空表示未参加或未录入。保存后学生端「考试成绩」立即可见；把分数清空再保存即撤回该学生的成绩。

## 教案

课程页「教案」卡片：新建、编辑、删除。教案内容为纯文本，按课程归属。教案也会随「课程备份」一起导出。

## 数字助手（页面右下角）

老师页面右下角的圆形按钮可以打开「教学助手」，它只读查询你自己的数据，不会修改任何内容。第一次登录会有一个提示气泡和轻微的呼吸动画指向按钮，点击即可打开；之后不再重复提示。

管理员和学生也有同名入口，分别是「系统助手」和「学习助手」，数据范围都限于本人可见的内容。

能回答三类问题：

- **怎么操作**：如「作业范围怎么设」「报告怎么发布给学生」，回答来自本手册原文
- **作业情况**：如「这次作业交了几份、哪道题错得最多」→ 汇总提交数、批改数、每题对/半对/错分布
- **学生评价**：如「张三这次作业怎么样」→ 逐题判定、评语、总分与批改报告

使用时注意：

- 只查得到你自己参与的课程；换老师账号登录看到的范围不同
- 对话保留在当前标签页，关掉标签页或点「新对话」即清空；切换页面不会丢
- 每次提问调用一次模型（约 2~6 秒），开销很小，不受「仅闲时批阅」限制
- 回答由模型根据查询结果组织，数字来自数据库；若有疑问，以页面上的实际数据为准

## 数字助手能回答哪些问题（示例）

主要流程的操作步骤都能问到（回答取自本手册各章节），数据类问题按你的课程归属实时查询。常用问法：

| 你想知道 | 直接这样问 |
|----------|------------|
| 我有哪些课、这门课整体情况 | 「这学期有哪些课」「高数课整体情况」 |
| 某讲的提交与批改进度 | 「第三讲交了几份」「还有哪些作业没批」 |
| 单次作业的错题分布 | 「第三讲哪道题错得最多」 |
| 某个学生的表现 | 「张三这次作业怎么样」「李四的考试成绩」 |
| 我配了什么提示词、用了多少 AI | 「我有哪些提示词」「这个月 AI 花了多少」 |
| 教案内容 | 「第三讲的教案」 |

操作类问题（建课、加学生、建讲次、划作业范围、批阅、复核、发布报告、备份、提示词）也可以直接问，返回对应章节的原文步骤。

## 在外部 AI 客户端里使用（MCP）

仓库根目录的 `mcp_server.py` 是一个只读 MCP 服务器，可挂到 Trae、Claude Desktop、Cursor 等支持 MCP 的客户端：

```json
{
  "mcpServers": {
    "gradelogy": {
      "command": "/绝对路径/.venv/bin/python",
      "args": ["/绝对路径/mcp_server.py"],
      "env": { "GRADELOGY_TEACHER": "teacher1" }
    }
  }
}
```

- 工具与页面助手完全相同：`ask_help`、`list_courses`、`list_lectures`、`lecture_status`、`find_student`、`student_report`、`list_exams`、`exam_scores`、`course_overview`、`pending_work`、`grading_queue`、`search_reports`、`ai_usage`、`list_prompts`、`get_prompt`、`lesson_plan`、`lecture_scope`
- 其中 `ask_help` 就是本手册的检索入口：接上 MCP 后问「怎么设置作业范围」「报告怎么发布」等，客户端会调用它取回上面这些章节的原文
- 只对老师账号开放：`GRADELOGY_TEACHER` 填的不是老师账号时，进程直接退出
- 只读，不含任何写操作；数据库路径默认取 `DATA_DIR/data.sqlite`，可用 `DB_PATH` 覆盖

## 常见问题

| 现象 | 处理 |
|------|------|
| 批改全部失败 | 检查 AI 设置与额度；日志中看 `HTTP 402` / `429` / `请求失败` |
| 提示模型不支持图片 | 换用支持图片输入的多模态模型；纯文本模型无法读取扫描件 |
| 批阅按钮是灰的 | 还没上传教师版答案，或还没勾选并保存作业范围 |
| 批阅超时（5 分钟） | 模型卡住或题量过大；换更快的视觉模型，或压缩 PDF 页数后重试 |
| 输出被截断 | 模型输出上限太小或题量过多；调大输出上限或减少一次批阅的页数 |
| 题目漏判 | 模型未返回的题不会凭空补；可在复核页手动补充，或重试批阅 |
| 批改很慢 | 整份 PDF 一次请求，页数越多越慢；可压缩 PDF 后重试 |
| 学生看不到成绩 | 确认已保存复核页（状态应为「已批改」），报告是否已「发布给学生」 |
| 学生看不到讲义 | 该讲次还没上传学生版讲义 PDF，到讲次页补传 |
