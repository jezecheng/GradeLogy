# 本地修复与重构记录

本记录对应 2026-11-18 代码审阅。修复先在本地验证，验收后按用户授权提交并推送至 `main`；生产发布结果以 GitHub Actions 为准。历史审阅报告保留原始证据，当前进度以本文件为准。

## 第一步：访问范围

- 附件原件、元信息和逐页预览统一检查资源归属。教师只能读取其管理课程的附件，以及其创建或获授权图谱的源资料；管理员可读取全部附件。
- 纵向学情分析必须同时指定课程和学生，避免同一学生的不同课程分析混用。
- 回归验证覆盖无关教师、学生标准答案隔离、图谱成员和跨课程分析。
- 验证：3 项隔离回归测试通过。

## 第二步：恢复后的登录会话

- 恢复数据库前原子更新实例会话版本，撤销所有浏览器的旧登录；固定签名密钥也不会使旧账号 Cookie 映射到恢复后的账号。
- 会话版本独立保存在 `.session_epoch`，不包含在备份包中。旧版本登录仅在实例尚未恢复时兼容。
- 验证覆盖同编号角色变化、其他浏览器、旧格式 Cookie 和恢复后的新登录。

## 第三步：重新批阅与报告安全

- 重新批阅先隐藏原结果，新结果写入时清除旧报告和逐题复习标记。全部复核后保存才公开；未完成复核不能发布报告。
- Markdown 链接转义属性引号并限制协议，保留常规链接和公式。
- 验证覆盖学生讲次页、报告、错题本、助手以及未复核发布请求和恶意链接。

## 第四步：图谱回滚

- 体检和分类快照记录应用后的图谱指纹，回滚在写锁内验证节点、关系、资料和文本块。后续变化或缺少版本信息时拒绝覆盖。
- 图谱修改和操作记录在同一事务完成。旧快照仍可保留查看，但不能安全回滚。
- 验证覆盖正常回滚、后续上传建图、跨类型编辑和旧格式快照。

## 第五步：删除规则

- 用独立删除服务统一处理学生移出、讲次、课程和账号删除；批改、标签、分析、薄弱点和复习标记与资源一起清理。
- 删除账号同时清理 AI 密钥和个人配置，保留共享课程的转交规则，图谱转交管理员。
- 原件与历史 AI 用量审计保留，失去归属的原件不能由教师或学生读取。外键全面启用和文件保留期限治理留待后续迁移阶段。
- 验证覆盖其他课程不受影响、子记录清理、事务失败回滚和共享资产转交。

## 第六步：AI 结果、配置与报告提示词

- 标签、题目清单、总评和报告结果先写入，再完成任务；写入失败先回滚，再标记失败，旧标签不会被半完成操作删除。
- 报告按讲次所属课程选择提示词，不再把讲次 ID 当作课程 ID。
- 环境 AI 密钥接管完整配置；缺少接口或模型时留空并报告配置错误。没有环境密钥时保留原有优先级：激活配置优先，环境 URL/模型仅作缺项默认值。
- 验证：17 项隔离回归测试通过，包含故障写入、不同课程/讲次编号和环境配置完整/部分覆盖。

## 第七步：应用实例与启动生命周期

- 应用工厂复制路由定义，每个实例使用独立签名器、数据库路径、批阅队列、通用 AI 队列和图谱调度状态。上传上限也读取新实例配置。
- `create_app()` 只创建应用和准备目录、日志、密钥；`initialize_app()` 显式建库、迁移和启动后台服务。迁移本身不再把活跃任务标成失败。
- 正式入口改为 `wsgi:app`，Docker 已同步；本地仍通过 `python app.py` 启动。自定义部署命令须相应更新。
- 验证覆盖双实例签名和数据库隔离、真实后台任务归属、单纯导入不建库或启动线程、迁移不干扰活跃任务。
