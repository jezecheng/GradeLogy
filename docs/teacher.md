# 老师手册

老师负责课程、学生名单、讲次与批改、考试成绩与教案。所有功能都在登录后的导航栏入口。

课程附件仅对有权访问本课程的老师开放；学生只能读取自己的原件和已加入课程的学生版讲义。纵向分析限定在当前课程内，不混用其他课程的学生记录。`TEMPORARY_GLOBAL_TEACHER_ACCESS` 默认开启，会暂时让所有老师访问所有课程；生产部署可设为 `0` 恢复课程成员隔离。

结构是「课程 → 讲次 / 考试」：一个课程下可以有若干讲次（每次作业即一讲）和若干场考试。

需要快速核对「某操作开始前必须准备什么」时，先看 [教师流程与前置条件](teacher-workflows.md)；本手册其余章节补充页面细节和常见问题。

| 层级 | 是什么 | 能做什么 |
|------|--------|----------|
| 课程 | 一学期的一门课 | 管学生名单、讲次、考试、教案与提示词 |
| 讲次 | 一次作业 / 一讲内容 | 上传教师版标准答案、收学生提交、AI 批阅与人工复核、发布批改报告 |
| 考试 | 一张卷 | 只录入分数与评语，不上传试卷、不做 AI 批阅 |

## 快速上手：30 分钟走完主流程

新账号第一次使用，按下面的顺序做一遍，就能把所有主要流程都过一遍（每一步都能在后面的章节里查到细节）：

1. **登录改密**：用管理员给的账号登录，初始密码 `123456` 时会被强制改密（见「登录与修改密码」）
2. **建课**：「我的课程 → 新建课程」→ 填课程名称与简介 → 创建（见「创建课程」）
3. **加学生**：课程页「学生」分区 → 下拉选学生 →「加入课程」（见「添加学生到课程」）
4. **配 AI**：导航栏「AI 设置」→ 填接口地址、API Key、多模态模型 →「测试连接」→「使用此 Key」（见「AI 设置」）
5. **建讲次**：课程页「讲次」分区 → 新建讲次，填标题（如 `01_绪论`）、说明、截止时间，上传**学生版讲义 PDF** 与**教师版标准答案 PDF**（见「新建讲次与上传讲义」）
6. **划范围**：讲次页「讲次资料与批阅准备 → 作业范围」→ 勾选教师版页码 →「保存并生成题目列表」→ 勾选本讲实际布置的题 → 保存（见「设置作业范围」）
7. **收作业**：学生自己上传，或老师点「代学生上传」批量补交（见「代学生上传作业」）
8. **批阅**：讲次页「提交与批阅」卡片点「AI 批阅」，任务进入后台队列（见「批阅方式」）
9. **复核**：点「逐题核对」，逐题改 OCR / 判定 / 评语并点「标记已复核」（见「人工复核」）
10. **生成与发布报告**：全部题目复核后，从复核页完成并生成报告；在报告页确认后用唯一的「一键发布给学生」同时公开报告和逐题结果（见「批改报告怎么发布给学生」）
11. **考试与备份**：课程页「考试」分区管理考试，「课程设置」中导出备份（见对应章节）

卡在某一步时，可以打开页面右下角的「教学助手」直接问操作步骤；也可以在 Trae / Claude Desktop 里通过 MCP 检索这本手册。

## 登录与修改密码

- 账号由管理员创建；初始密码为 `123456` 时，首次登录必须先改密
- 顶部或手机底部「更多 → 账号与密码」进入改密页；忘记密码找管理员重置
- 连续 40 分钟无操作会显示提醒，45 分钟无操作后自动退出；后台任务状态刷新不会延长登录时间。未保存的内容不会自动提交
- 登录后默认进入「我的课程」
- 管理员恢复备份后，所有人需要用恢复后的账号重新登录。

## 创建课程（建课、改课名、删除课程）

建课：「我的课程 → 新建课程」→ 填写名称与简介 → 创建。课程卡片显示人数、讲次、考试和批阅待办；进入课程页可编辑名称与简介。

只有课程创建者能删除课程；共同管理老师不能删课。删除课程会连同该课程的讲次、考试、提交与教案一起删除，操作前建议先导出课程备份。

## 添加学生到课程（把学生加进课程、名单导入）

把学生加进课程：进入「学生」分区，在可加入名单按姓名、账号或学籍号搜索并多选 →「检查所选名单」核对人数与姓名 →「确认加入所选学生」。可以返回修改名单；没有默认全选。

- 候选只列出管理员已创建、**处于启用状态**且尚未加入本课程的学生账号；提交时服务端还会重新校验，重复提交不会重复加入
- 提交后会显示新增、已在课程中和不可用账号的数量；无效账号使用通用提示，不泄露停用或不存在账号的详细信息
- 建号由管理员负责；老师端不建号，也不再提供课程内的 CSV 批量导入
- 批量加很多人时，请管理员在「用户管理 → 批量创建」用姓名 CSV 建号，再回这里批量加入

## 移出学生

名单每一行最右侧是「移出」按钮，点击后需在弹窗里二次确认。

移出会删除该学生在本课程的提交、批改、考试成绩、分析、薄弱点和复习标记。账号与其他课程不受影响；需要保留记录时应停用账号。删除前先备份。

删除讲次或课程也会清理其相关教学记录。原始附件和历史 AI 用量记录暂保留在服务器，失去资源归属的附件不能由教师或学生下载；备份中的旧数据仍需由管理员按保留规则管理。

## 多名老师共同管理同一课程

课程页「课程设置 → 共同管理老师」展示本课程的所有老师：

- **创建者**：建课的人，可以编辑课程名称与简介、添加 / 移除其它老师，也只有他能删除课程
- **共同管理**：可进入课程、管理学生名单、建改讲次与考试、批阅与发布报告，但不能编辑课程信息或增删老师
- 添加方式：点「＋ 添加老师」，从老师账号下拉中选择（只列出尚未加入本课程的老师）
- 移除后对方账号与其它课程不受影响；「我的课程」列表会显示「N 位老师共同管理」

## 新建讲次与上传讲义

课程页「讲次」分区：填写标题（如「01_绪论」，讲次按标题升序排列）、说明、截止时间，可同时上传**学生版讲义 PDF**（发给学生的原卷，学生端可预览）与**教师版标准答案 PDF**（AI 批阅时作参考），两份都可稍后补传。一个课程可以有任意多个讲次。

- 学生版讲义 = 学生看到的卷子；教师版标准答案 = AI 批阅的对照材料，两者不要传反
- 没上传学生版讲义，学生仍可提交作业，但看不到原卷预览
- 没上传教师版标准答案，AI 批阅和自动批阅都不会执行

## 编辑讲次与截止时间

讲次页「讲次资料与批阅准备 → 讲次信息」可改标题、说明与截止时间，保存即生效；清空截止时间再保存即取消截止限制。课程页讲次表格里会显示该讲有无「学生版 / 教师版」文件。

讲次页「标准答案（教师版）」卡片支持上传或更换答案 PDF；上方「学生版讲义」卡片用于上传发给学生的原卷。AI 批改以教师版 PDF 为参考。

## 代学生上传作业

讲次页「提交与批阅」卡片右上角「代学生上传」：选择学生后，可一次选择多张图片 / PDF，或在手机上直接拍照。文件先进入**草稿箱**，可预览缩略图、逐个删除，点「确认上传」才真正写入。

- 同一批多图记为**一次提交**，列表显示 `查看扫描件 1/3`、`2/3`，AI 批阅会按顺序合并
- 单文件 ≤20MB，一次最多 20 个文件
- 该学生已有提交时再次代传会先确认；确认后覆盖该学生本讲的**全部历史提交**，清除关联的逐题批阅、报告和复习标记，再以新文件重新处理。旧附件与 AI 用量审计记录仍保留

## 设置作业范围（只批改布置的题目）

上传教师版标准答案后即可使用「作业范围」卡片。AI 批阅本身也依赖教师版答案，因此标准流程是先上传答案、再划定范围：

1. 在「教师版页码」勾选本讲实际对应的答案页（这一步与生成题目清单合并，不再需要单独分析按钮）
2. 点「保存并生成题目列表」，AI 用选中的答案页列出题号、可折叠题干与说明（约 20~60 秒）
3. 勾选本讲实际布置的题目（可「全选 / 全不选」）并保存作业范围；保存范围不会调用 AI
4. 若希望学生提交后自动批阅，需单独点「生成/重新生成知识点标签」并等待当前范围生成成功；老师手动批阅仍可不依赖标签
5. 之后每份作业的 AI 批阅只处理勾选的题目，未勾选的题目不会出现在批阅结果里

必须至少勾选一道题并保存，AI 批阅才会执行；没有教师版答案或没有划定范围时，即使学生已经提交作业，批阅按钮也不可用。更换答案或页码后，旧题目清单和范围会立即失效，必须等新清单生成并重新选择，避免把旧范围用于新答案；分析失败时可重试，旧范围不会继续用于批阅。

如果本讲已经有批阅记录，重新选择答案页、重新提取题目清单或改变已保存的作业范围时，页面会先说明影响并要求确认。确认后会清除本讲所有提交的旧逐题批阅、报告、逐题复习标记、旧标签和相关分析，并重算错题/薄弱点；学生原始提交文件与 AI 操作/用量审计历史保留。其他讲次仍能支持的同名薄弱点会保留并按其余公开结果重新统计。

新题目清单按出现顺序把大题编号为 `1`、`2`……。有小问的大题在清单中可展开，母题题干保留在大题行；母题勾选可一次选择全部小问，也可以只勾选部分小问。批阅、知识点标签、逐题复核和报告中的每个小问都独立编号为 `1.1`、`1.2`……；无小问的大题本身作为一个独立批改项。原卷题号仅用于 AI 对照，不再作为系统显示编号。

## 教师版页码怎么勾选（只发送相关页）

「作业范围」卡片里还有一块「教师版页码」：系统把教师版 PDF 逐页渲染成缩略图，勾选本讲作业实际对应的页。

- 学生交的是 PDF 的第几页，这里就勾第几页；批阅时只把这些页发给模型
- 支持按打印习惯填范围：`1-5, 8, 10-12`，点「按范围勾选」自动对应缩略图
- 也提供「全选 / 全不选」；**全不选并保存 = 发送整份答案**
- 点「保存并生成题目列表」会同时保存页码并立即生成题目清单，不需要再点其他按钮；未保存页码或全不选时分析、批阅整份答案
- 更换教师版 PDF 会清空已选页码、题目清单和作业范围（答案已变化），需要重新勾选页码并等待新题目清单

按一份 26 页学生卷 + 20 页答案算，答案只勾 4 页可把发给模型的图片从 46 张降到 30 张，输入 token 减少约三成。

## 知识点标签与薄弱点分析

保存作业范围不会调用 AI。更换答案、答案页或作业范围后，原 AI 标签不会自动更新；需要时在「作业范围」单独点「生成/重新生成知识点标签」，系统为当前勾选题目更新标签并显示在表格中。该操作进入后台 AI 队列，可在任务入口观察状态；失败不影响已保存范围，可显式重试。
每个独立批改项最多生成 6 个知识点标签；有小问时按小问分别标注。

标签用于两种分析。横向分析需要已有标签和逐题判定记录；纵向分析需有该学生跨讲次的批阅数据：

- **横向（同一讲、全班）**：讲次页「知识点分析（全班）」→「分析知识点」。系统把每道题题号、关联知识点、全班错误率与典型错误评语交给 AI，找出同学们普遍薄弱的知识点，并给出讲评课的教学建议（整体掌握情况、高风险知识点、讲评课建议）。
- **纵向（同一学生、跨讲次）**：学生详情页「纵向知识点分析」→「分析薄弱点」。系统汇总该生各知识模块的累计掌握度、跨讲次趋势、反复出现的作答习惯问题，按标签找反复出现的薄弱点，并给出「先补前置基础、再练综合应用」的行动方案。

讲次页标签旁的 `错 + 半对 / 已判定记录数` 是数据库汇总，不是 AI 结论；分母包含「无法判定」，不包含空判定，悬停可看关联题号及各判定数量。它先于 AI 文本分析显示；点「分析知识点」才会另外生成全班共性问题和教学建议。`0/1` 代表没有错/半对记录，不一定代表全员答对，因为也可能是无法判定。

两类分析都有系统内置默认提示词，也可复制成自己的副本修改，再到课程页「课程设置 → 提示词配置」选择本课程使用哪一条，详见下文「我的提示词」。

每次分析都会新增一条记录并保留上一次结果；在「AI 消耗记录」中对应「知识点标注」「横向知识点分析」「纵向知识点分析」。标签与批改题号按前导数字匹配；更换答案或作业范围后，如需更新标签，请显式点击「生成/重新生成知识点标签」。

### 学生薄弱点与老师操作的关系

上面生成的标签不仅用于两份 AI 分析，也直接决定学生端「我的薄弱点图谱」和「错题本」的内容。老师端没有单独的薄弱点编辑页，管理是间接的：

| 老师操作 | 对学生薄弱点的影响 |
|----------|--------------------|
| 保存作业范围 | 决定 AI 批阅哪些题目；不触发 AI 标签生成 |
| 显式生成/重新生成知识点标签 | 决定每道题关联哪些知识点；没有标签的题不进入薄弱点统计 |
| 已公开作业的复核页修改判定并保存 | 公开门槛仍有效时，学生可见结果和薄弱点按新判定刷新；保存草稿会撤回公开状态 |
| 课程详情关联知识图谱 | 标签能匹配图谱节点时，学生端会把命中同一节点的多个标签合并成一张卡并在星图中点亮；匹配不到时仍以标签名单独成卡，但不进入星图 |
| 重新 AI 批阅 | 入队时撤回旧公开结果，清除旧报告与逐题复核标记；新结果复核并重新发布后可见 |

更新时机与规则：

- 仅统计 `report_published=1` 的提交；发布或撤回时系统重算薄弱点。未发布的复核结果不会进入学生薄弱点或错题本
- 同一份作业反复保存不会重复创建薄弱点：始终按「学生 + 课程 + 知识点标签」保留一条，计数覆盖为最新结果
- 学生在自己页面设置的「已复习 / 已掌握」状态与备注，老师重新批改时不会被覆盖
- 同一讲次重复批改不会把学生的状态打回「薄弱」；只有**后续讲次**再次被判「错」或「半对」时，才自动回退为「薄弱」
- 学生移除过的知识点，同一讲重批不会恢复；新讲次再次做错时会自动恢复为「薄弱」
- 老师端看不到、也不能直接修改学生的复习状态；如果标签或判定有误，应修正标签或判定，再由学生自行标记、移除或等待新讲次结果

如果学生反馈薄弱点明显不对，按下面顺序排查：

1. 讲次「作业范围」里该题的「知识点标签」是否为空或过于宽泛 → 点「生成/重新生成知识点标签」
2. 复核页该题判定是否误判为「错 / 半对」→ 改正后保存；已发布结果会同步刷新，未发布结果需发布后才进入学生统计
3. 课程是否关联了合适的知识图谱、标签名称能否匹配节点 → 未匹配的标签仍会出现在列表，但不会点亮星图
4. 需要了解班级或个人整体情况时，用「知识点分析（全班）」和「纵向知识点分析」；这两份分析只读，不会改动学生端数据

## 学科知识图谱（上传资料冷启动）

知识图谱是为了补上「只知道哪题错、不知道为什么会错」的缺口。批改结果能告诉老师某道题错了，但横向分析容易停留在题号罗列，纵向分析也很难解释「这次综合题卡壳」与「前几讲哪个基础没打牢」之间的联系。把教材、考纲、讲义沉淀成概念与前置关系后，分析就有了学科结构作为参照，可以把错题映射回知识点及其前置链，而不是只罗列错题。

它当前承担三件事：一是作为学科知识的统一底稿，同一学科的老师共用一套概念命名与关系；二是持续吸收新资料，越用越完整；三是为后续横向 / 纵向分析的根因诊断提供「前置知识点 → 衍生知识点」的依据，让建议从「多练这类题」变成「先补哪个前置概念」。

导航栏「知识图谱」按学科沉淀概念与前置关系，资料上传后自动抽取，后续可继续追加，不需要一次性准备齐全。所有教师都可以查看图谱并将其关联到自己可访问的课程。正常权限模式下查看/关联不授予编辑权限；但 `TEMPORARY_GLOBAL_TEACHER_ACCESS=1`（默认）时，所有教师临时获得所有图谱的编辑权限。

- **新建图谱**：填写学科（如「高中化学」）、图谱名称，可选学段与说明。图谱按学科共享：所有老师可查看，创建者与管理员默认拥有管理权限。
- **协作权限**：正常权限模式下，详情页「协作成员」由管理角色维护。**管理**可改名、删除图谱、分配成员；**编辑**可上传 / 删除资料、下载资料、归档 / 还原资料、反向 / 删除关系、执行体检与智能去重；**使用**可下载资料。所有教师都可只读浏览并把图谱关联到自己可访问的课程；协作名单不再是课程关联的前置条件。若 `TEMPORARY_GLOBAL_TEACHER_ACCESS=1`，所有老师临时获得所有图谱的编辑权限（不含图谱管理权限）。
- **编辑信息**：管理角色可在详情页点「编辑信息」修改图谱名称与说明，不影响已建的概念、关系与资料；学科不可修改，需要更换学科时请新建图谱。
- **课程关联**：课程详情页「关联知识图谱」列出系统内全部图谱，可勾选一个或多个，保存后整体替换原有选择；不勾选则解除全部关联。一个图谱可以被多门课程共用，关联本身不复制资料或节点，也不授予编辑或源资料下载权限。
- **上传资料**：支持 PDF / Word（DOC、DOCX）/ Markdown / TXT，可一次多选，单份默认上限 500MB（可用 `KG_MAX_UPLOAD_MB` 调整，与作业附件的 20MB 上限互不影响）。系统按页抽取文字并按约 3000 字切块，逐块交给 AI 抽取概念、定义、别名，以及「前置 / 包含 / 相关」三类关系；带依据与置信度。多份资料会排队逐个建图，避免同时请求触发模型限流；**建图过程中可以继续上传**，新资料自动进入待处理队列。
- **增量合并与防环**：新增资料只合并差异，同名或别名概念会归并到同一节点，关系去重；相同内容的文件按文件指纹自动跳过。写入前置关系前会检查是否形成环，成环的关系直接跳过，并在建图结果里提示跳过数量。
- **状态查看**：每份资料显示「○ 待处理 / 处理中 / ✓ 已完成 / ✕ 处理失败」，表格上方汇总各状态数量；建图期间通过轮询更新状态，不再整页刷新，因此不会打断正在选择的新文件。失败原因（如扫描版 PDF 没有文字层、模型输出被截断）会显示在资料下方。单份资料最多取前 12 万字用于建图。
- **折叠查看**：资料区在超过 8 份时默认折叠，标题上实时汇总各状态数量，并显示最近一份文件名；展开后表格高度受限、表头吸顶，资料很多时也不会把整页撑长。概念节点与关系边两块内容同样可分别折叠。
- **分层图**：按「前置 → 衍生」关系自动分层，第 1 层是最基础的概念；实线为前置、虚线为包含、点线为相关。节点过多时只展示关联度最高的 80 个并提示未展示数量；检测到存量前置环时会在图下方单独列出环上概念和建议优先检查的关系。
- **关系维护**：关系边表格提供「反向 / 删除」。反向仅对前置关系开放，系统会先排除原边再检查是否会制造新环；重复的反向边自动合并。
- **图谱体检**：模型给出结构化建议，系统校验后供老师确认。应用前保存快照；之后没有建图或编辑时可回滚，有后续变化则拒绝覆盖。旧快照不能验证版本时，请使用完整备份或手工调整。
- **智能去重**：系统先按「别名/名称归一冲突、跨分类共享邻居、同分类关键词重叠」三路召回疑似重复的概念，候选组并发交给 AI 判定哪些应合并为一个节点；界面实时展示逐组进度，中途失败或服务重启后可点「继续去重」从未完成组续跑，已完成组不会重复调用模型。结果以合并簇形式可视化预览，可逐簇点「暂不合并」排除，确认后应用。应用前保存快照，无后续变化时可回滚；单组 AI 出错只记录、不影响其它簇。
- **运营指标**：详情页顶部显示资料、节点、关系、文本块数量，以及语料文件与数据库表的空间占用、累计构建用时、Token 和涉及模型；「存储明细」给出各数据表的记录数与估算占用。
- **概念邻域**：点击分层图中的节点或概念表格里的名称，进入该概念的邻域页，分三列查看「直接前置 / 当前概念 / 直接延伸」，下方列出包含与相关概念及教材依据。
- **出处回收**：删除某份资料时，只移除仅由它支撑的概念与关系；仍被其他资料引用的节点会保留。
- **资料归档减容**：已建图完成（或失败）的资料，可在资料表格里勾选后批量「归档」，或单行「归档」。归档把源文件移出 `uploads/` 到独立归档目录，但**保留全部建图历史**（元数据、文本块、概念、关系、体检记录），图谱照常可用；归档文件不计入语料空间、也不进入系统备份，以减小备份体积。需要时可「还原」把文件移回。建图中或待建图的资料不能归档。
- **备份与迁移**：未归档资料的原始文件保存在 `uploads/kg/<图谱ID>/`，节点、关系、体检记录与成员保存在数据库；都会进入系统备份包。已归档资料的源文件位于归档目录，不进入备份，还原后才会重新计入。

当前版本已完成图谱沉淀、治理与协作；错题标签到前置缺口的自动根因联动仍在后续版本提供。

## 查看单个学生的进度

课程页学生名单里点姓名（或「进度」）进入学生详情：上方是该生在本课程每一讲次的提交次数、状态与正确率（可直达批阅页），下方是该生所有考试的得分与评语。学生资料（姓名 / 学籍号）与登录密码由管理员统一维护，老师端只读。

## 批阅方式（整份原卷，不切题）

讲次页不需要「提取标准答案」；但必须先上传教师版答案并划定作业范围，未上传答案或未划定范围时批阅不会执行。点提交卡片上的「AI 批阅」时，系统会把两份材料一起交给模型：

1. 学生提交的作业（PDF 或扫描图片）
2. 作业的教师版标准答案 PDF

系统把两份文件的每一页渲染成图片后一次性发送，模型看到完整原卷，逐题输出题号、学生作答 OCR、标准答案要点、判定、建议分数与评语，不做任何题目裁剪。需要「AI 设置」里选择**支持图片输入**的多模态模型，输出上限建议 ≥32k。

单份批阅实测：约 26 页图片、45 题，DeepSeek 视觉版约 90 秒、4.5 万 token；模型卡死时 5 分钟超时后直接报错，不会反复重试。

## 后台批阅、自动批阅与批阅失败

**后台批阅**：点「AI 批阅」后任务进入后台队列，页面立即返回并显示「排队中 / 批阅中」。可以继续给其他学生提交批阅，也可以关闭浏览器或离开页面，任务会继续执行并把结果写入数据库；回到讲次页即可看到「重新批阅」和最新结果。默认同时处理 2 份，避免触发模型限流，可通过环境变量 `GRADING_CONCURRENCY` 调整（1~4）。服务重启时未完成的任务会被标记为失败并提示重新提交。教师页顶部始终保留「任务」入口，点击查看正在执行及最近完成、失败的记录；手机底部也有入口。点击记录可回到对应页面。

**自动批阅**：系统默认每 6 小时扫描一次，也会在学生/老师上传、保存范围或标签成功生成后尝试立即入队。自动流程要求教师版答案、已生成的题目清单、至少一个已保存范围题目、当前范围标签已成功生成、完整 AI 配置且非演示模式，并且没有被「仅闲时批阅」规则拦截。自动扫描先用课程创建者的 AI 配置与自动批阅次数上限；共享课程下手动批阅则使用当前操作老师自己的 AI 配置。默认每个学生每讲仅前 3 次提交自动批阅，之后需老师手动触发；上限可通过课程创建者的「自动批阅次数」设置调整。任何条件不满足时提交仍保留为待批阅，老师仍可手动批阅（手动流程不要求知识点标签）。可通过环境变量 `AUTO_GRADE=0` 关闭定时扫描（上传/保存范围/标签完成时的即时触发仍会尝试），或用 `AUTO_GRADE_HOURS` 调整扫描间隔（默认 6 小时）。

**批阅失败怎么办**：先看讲次页的失败提示与「AI 消耗记录」，再到「AI 设置」展开对应连接，点「测试连接」，确认 Key 有效、额度充足、模型支持图片输入；改好后在提交列表点「重新批阅」。常见原因与处理见文末「常见问题」。

## AI 设置

桌面从侧栏进入；手机点底部「更多 → AI 设置」。连接与批阅设置分列展示，窄屏自动改为单列。当前连接默认展开，其他连接和新增表单按需展开；模型参考、输出上限和价目更新收在折叠区。

配置项：

| 项 | 说明 |
|----|------|
| 当前状态 | 已配置时显示「当前 AI API 已配置」、正在使用的名称、基地址、掩码 Key 与模型 |
| 多组配置 | 可保存多套互相独立的配置（如阿里云一套、腾讯云两套），每套分别保存基地址、Key 和模型 |
| 切换 | 列表里点「使用此 Key」切换当前生效的一套，切换后模型与基地址一起恢复 |
| 接口地址 | 任意 OpenAI 兼容服务，如 `https://tokenhub.tencentmaas.com/v1` |
| API Key | 新增时必填；编辑配置时旧 Key 不会回显，替换 Key 留空表示保留原值；页面仅展示掩码，删除当前 Key 后会自动切换到最近保存的一组 |
| 模型 | 展开连接卡片后单独填写并保存；必须是**支持图片输入的多模态模型**，如 `deepseek-v4.1-flash`（腾讯云 TokenHub 推荐）、`glm-5.3-flash`、`gpt-4o` |
| 演示模式 | 未配 Key 时可用，生成占位批阅结果，仅用于走通流程 |
| 测试连接 | 每套连接都有独立的「测试连接」，只使用该套配置的地址、Key 与模型，不受当前选中项影响 |

「AI API 配置」位于页面最上方、模型参考与批阅设置之前；切换 Key 后模型清单会按新的基地址重新识别。

部署环境设置了 AI 密钥时，接口地址、密钥和模型必须成套配置，页面配置不会补齐缺项。没有环境密钥时，激活的页面配置优先，环境接口或模型仅作缺项默认值。

模型不再有全局下拉框，而是跟随每套配置保存，切换配置时自动恢复对应模型。服务端若通过环境变量注入了 `AI_API_KEY`，Key 由部署方接管，页面上的管理不生效；只注入 `AI_API_URL` 时仍可正常保存多套配置，保存的配置优先。

## AI 消耗记录

想问「AI 花了多少钱」「这次批阅用掉多少 token」，看这里的「AI 消耗记录」。讲次详情、逐题核对和教师版批改报告页面底部会显示「AI 消耗记录」，用于查看作业范围分析、作业批阅、讲次汇总与报告生成评价的消耗。
左侧导航的「AI 用量」集中显示当前教师自己的模型请求，可展开查看服务商请求 ID、状态、重试次数、Token、耗时、错误、服务商用量与计价快照；每页显示 100 条，可翻页查看历史。右上角后台任务队列中的任务和完成通知都跳转到此页。

- 每次点击都会生成一条新的操作记录；重新分析、重新批阅和重新生成不会覆盖旧记录，失败的操作也会保留
- 任务只有在结果写入成功后才显示成功；写入失败会回滚本次写入并标记失败。
- 每次记录展示输入、输出、合计 token、整体耗时和预估费用；发生自动重试时，各次请求分别保存，页面展示合计值与请求次数
- token 来自服务商返回的 `usage`，数据库同时保存可获得的缓存 token 与推理 token；服务商未返回时显示「未知」，不会按 0 计算
- 费用按操作开始时的模型输入价、输出价和高峰倍率快照估算，仅供成本参考，实际费用以服务商账单为准；缺少 token 或模型价格时费用显示「未知」
- 演示模式不产生真实消耗记录；仅在本地重排报告、没有调用 AI 时也不记录。数字助手对话和「测试连接」不进入 AI 用量、模型请求或应用访问日志

## 我的提示词（批改 / 报告 / 知识点分析）

导航栏「我的提示词」按四类管理提示词：批改、报告、横向分析、纵向分析。

- 每类系统内置一条默认提示词，全局可用、不可删除、不可修改；代码升级时内容会自动更新。
- 点「复制为我的提示词」得到可自由修改的副本，改到满意后在课程页选用。
- 自建提示词可命名、修改、复制多份做对比测试、删除；删除后引用它的课程自动回落到系统默认。
- 只需写角色、规则与要求，JSON 输出格式由系统自动追加，保证结果能被解析。
- 两类分析提示词用占位符引用输入数据，保留占位符即可按讲次 / 学生自动填充；新建弹窗与每条提示词上方都会列出可用占位符：
  - 横向：`{subject_and_course}`、`{lecture_name}`、`{total_students}`、`{aggregated_question_stats}`
  - 纵向：`{lecture_count}`、`{subject_and_course}`、`{student_name}`、`{lecture_range}`、`{module_mastery_stats}`、`{kg_weakness_chains}`、`{error_habit_stats}`、`{trend_data}`
  - 自定义时若删掉部分占位符，系统仍会把未注入的数据附在提示词末尾，不会让模型「无数据可依」。

课程页「课程设置 → 提示词配置」为本课程分别选择批改、报告、横向分析、纵向分析提示词；不选即用系统默认。
共同管理该课程的其他老师自建的提示词也会出现在下拉里。

## 人工复核（怎么复核、逐题核对）

AI 批阅完成后，逐题核对并标记已复核。全部复核只完成内部审核，不会自动对学生公开；报告和逐题结果由报告页的同一个发布开关控制。「保存草稿」会撤回此前的公开状态。

讲次页的提交列表，每份提交有两个入口：

- **AI 批阅 / 重新批阅**：把学生作业与标准答案整份交给模型，一次返回逐题结果
- **逐题核对**：打开发布前的复核页
- **跳过人工复核并生成报告**：有 AI 批阅结果但尚无报告时可用；会明确标注人工复核已跳过，只生成未发布的报告。学生发布仍必须进入报告页手动操作。

AI 批阅完成后，讲次列表会显示各题 AI 信心指数的均值，每题的复核卡片旁也会显示本题信心指数；红色偏低、绿色偏高。它是模型对“本题判定可靠性”的自评，不是正确率或人工审核结论；无法判定、题页未确认时会限制为低信心。

桌面复核页两栏对照；手机在每题内切换「学生作答 / 标准答案」，输入会保留：

| 左 | 右 |
|----|----|
| 可编辑的 OCR 文本框、判定、评语 | 该题标准答案（可修正） |

- 复核时每题有判定下拉：对 / 半对 / 错 / 无法判定；可修改评语
- 复核只按判定统计，作业不单独赋分：正确率为「对」的独立批改项数 ÷ 独立批改项总数；无法判定也计入分母，半对不计为完全答对
- 学生作答和标准答案预览会按识别到的小题编号分行显示；只调整阅读排版，不会改动答案内容
- 默认定位首个待复核题，可筛选待复核、全部或无法判定，也可直接跳题。逐题修改自动保存，失败时保留明确提示。
- 全部题目复核完成后，点击「完成并生成评阅报告」会先保存审核状态，再跳到报告页启动后台生成；已有报告时显示「保存草稿、打开评阅报告、重新生成评阅报告」。
- 若暂不逐题人工核对，可从讲次列表选择「跳过人工复核并生成报告」。报告页和报告正文都会注明 AI 自动批阅、人工复核已跳过；该操作不会替你发布。
- 复核完成本身不公开学生结果；公开入口只在评阅报告页。
- 页面右上角「查看原始扫描件」可并排打开学生原卷 PDF 核对

原始扫描件按需打开；桌面可调整宽度，窄屏独立查看。复核按正确率统计，不单独赋分。

## 批改报告怎么生成和发布给学生

报告生成与逐题复核是两个环节；**对学生的公开只有一个入口**，在评阅报告页。

1. 在「逐题核对」页逐题复核。每题修改会自动保存；每道题都必须标记完成复核。
2. 全部复核后点「完成并生成评阅报告」。系统保存审核状态，进入报告页并在后台生成 Markdown 报告。已有报告时，可先「打开评阅报告」，需要同步最新逐题结果时选择「重新生成评阅报告」。
3. 生成期间报告页会显示后台状态并自动刷新。失败时页面显示错误，可以修复 AI 设置后重试；已有旧报告时失败不会覆盖旧报告。
4. 检查报告正文，可在「编辑报告内容（Markdown）」中手动修改并保存。重新生成会覆盖报告正文，包括手工修改内容；有现成报告时系统会要求确认。
5. 报告页可下载高清 PNG 长截图或 Markdown。PNG 按当前报告页渲染（含公式与表格），根据屏幕 DPI 以 2–3 倍比例导出；报告特别长时会自动降低倍率以适配浏览器画布限制。确认后在报告页点「一键发布给学生」。该开关同时公开评阅报告、逐题结果和相关错题/薄弱点数据；「撤回发布」会一并隐藏。

报告由服务端生成逐题明细、判定统计、失分归因和评价。正常模式下报告任务会调用 AI 写评价；AI 未配置完整或调用失败时，本次任务会失败且不会用不完整内容覆盖旧报告。演示模式跳过 AI，可生成结构性报告。复核页独立的 AI 总评生成/编辑区已移除，不影响报告自身的 AI 评价。

其他说明：

- 人工复核完成不等于学生可见；学生端、助手、错题本和薄弱点均以 `report_published` 为统一门槛。
- 保存草稿会撤回此前公开状态。重新批阅会隐藏旧结果并清理旧报告，待新结果复核、报告生成后再发布。
- 报告支持安全链接和数学公式；危险链接协议不会渲染为可点击链接。
- 已发布报告保存 Markdown 修改后学生端同步看到更新；撤回后学生不可见。
- 「下载 .md」可导出报告源文件。报告包括逐题判定（✅/⚠️/❌）、统计、失分点归因，以及 AI 生成的评价内容（若有）。

## 课程备份

课程页「课程设置 → 课程备份」点「导出课程备份」，将讲次文件、提交和报告打包下载。仅创建者与共同管理老师可导出。

压缩包按「课程 → 讲次 → 学生」整理：

```text
课程名/
  讲次名/
    教案-学生版.pdf
    教案-教师版.pdf
    学生用户名/
      批改报告.md
      提交作业/
        原始作业文件.pdf
```

- 教案取讲次页上传的学生版讲义与教师版答案；未上传的一侧不会出现在包内
- 每个学生一个文件夹，使用登录用户名；多次提交会合并到「提交作业」，重名文件自动加序号
- 批改报告取该生最新一次已生成的报告；尚未批阅的学生不会生成报告文件
- 同名讲次会自动追加序号（如「第1讲 极限 (2)」）避免互相覆盖
- 生成后直接下载，同时服务器保留 1 天，期间可在卡片下方再次下载；过期自动清理

## 考试与成绩录入

课程页「考试」分区可新建考试（名称、日期、满分、说明）；考试只记分数，不上传试卷、不走 AI 批阅。

点考试进入录分页：每名学生的状态为「待录入 / 缺考 / 已录入」。填写分数或评语并保存后立即对该生可见；零分是有效成绩。待录入表示尚未处理，缺考必须由老师明确选择，不会按零分计入。把状态改为待录入会清除当前分数与评语；标记缺考会清除分数、保留评语，并在操作前提示确认。

## 教案

纯文本教案的服务端功能仍保留，当前课程页面没有独立编辑入口。课程备份中的「教案」文件指讲次上传的学生版讲义与教师版答案，不包含独立教案正文。

## 教学助手

教师从页面顶部「教学助手」打开。助手只读，不修改教学记录；手机面板避开底部导航。教师可访问的数据范围受部署环境变量 `TEMPORARY_GLOBAL_TEACHER_ACCESS` 控制：默认 `1` 时暂时全局开放课程访问，设为 `0` 后按课程成员过滤。

管理员和学生也有同名入口，分别是「系统助手」和「学习助手」，数据范围都限于本人可见的内容。

能回答三类问题：

- **怎么操作**：如「作业范围怎么设」「报告怎么发布给学生」，先从教师流程表、老师手册和知识图谱说明检索步骤与前置条件
- **作业情况**：如「这次作业交了几份、哪道题错得最多」→ 汇总提交数、批改数、每题对/半对/错分布
- **学生评价**：如「张三这次作业怎么样」→ 逐题判定、评语、公开状态与批改报告

使用时注意：

- 在 `TEMPORARY_GLOBAL_TEACHER_ACCESS=0` 时只查得到你参与的课程；默认 `1` 时教师助手暂时可查全平台课程。生产部署应根据数据隔离要求设置该值，换老师账号不一定能隔离数据
- 对话保留在当前标签页，关掉标签页或点「新对话」即清空；切换页面不会丢
- 一次提问最多可能经过 4 轮模型请求，并触发多次工具调用；响应时间会随问题、数据量和模型服务状态变化，不受「仅闲时批阅」限制
- 回答由模型根据查询结果组织，数字来自数据库；若有疑问，以页面上的实际数据为准

## 数字助手能回答哪些问题（示例）

主要流程的操作步骤都能问到（回答取自本手册各章节），数据类问题按 `TEMPORARY_GLOBAL_TEACHER_ACCESS` 的当前设置实时查询。常用问法：

| 你想知道 | 直接这样问 |
|----------|------------|
| 我有哪些课、这门课整体情况 | 「这学期有哪些课」「高数课整体情况」 |
| 某讲的提交与批改进度 | 「第三讲交了几份」「还有哪些作业没批」 |
| 单次作业的错题分布 | 「第三讲哪道题错得最多」 |
| 某个学生的表现 | 「张三这次作业怎么样」「李四的考试成绩」 |
| 我配了什么提示词、用了多少 AI | 「我有哪些提示词」「这个月 AI 花了多少」 |
| 教案内容 | 「第三讲的教案」 |

操作类问题（建课、加学生、建讲次、划作业范围、批阅、复核、发布报告、备份、提示词）也可以直接问，返回对应章节的原文步骤。

## 在外部 AI 客户端里使用（MCP）

仓库根目录的 `mcp_server.py` 是一个 stdio 只读 MCP 服务器，可挂到 Trae、Claude Desktop、Cursor 或其他支持 stdio MCP 的客户端。客户端需能在 GradeLogy 数据库所在环境启动 Python 进程；WorkBuddy 等产品需先确认 MCP 客户端是否支持 stdio。部署在云端的客户端不能直接读取本机 SQLite，需另行提供受认证的远程 MCP 接入：

```json
{
  "mcpServers": {
    "gradelogy": {
      "command": "/绝对路径/.venv/bin/python",
      "args": ["/绝对路径/mcp_server.py"],
      "env": { "GRADELOGY_TEACHER": "teacher1" }
    }
  }
}
```

- 工具与页面助手完全相同：`ask_help`、`list_courses`、`list_lectures`、`lecture_status`、`find_student`、`student_report`、`list_exams`、`exam_scores`、`course_overview`、`pending_work`、`grading_queue`、`search_reports`、`ai_usage`、`list_prompts`、`get_prompt`、`lesson_plan`、`lecture_scope`
- 其中 `ask_help` 是教师手册检索入口：问操作或前置条件时应先调用它。结果明确要求按「必须条件 → 可选/推荐项 → 操作顺序 → 完成后状态」回答，并区分手动/自动批阅、复核/报告/发布；资料未说明的条件不得推测。检索源为教师流程表、老师手册和知识图谱说明，不包含历史审阅记录
- 更新并拉取代码后，需让 MCP 进程指向新版仓库，并在 WorkBuddy/其他 MCP 客户端中重载或重启该服务器，使新版工具描述重新初始化；`ask_help` 随调用读取本地正式手册
- 只对老师账号开放：`GRADELOGY_TEACHER` 填的不是老师账号时，进程直接退出
- 一个 MCP 进程固定使用一个 `GRADELOGY_TEACHER` 身份；不是每个 WorkBuddy 用户单独授权，勿把共享 MCP 服务误当成用户级鉴权
- 只读，不含任何写操作；数据库路径默认取 `DATA_DIR/data.sqlite`，可用 `DB_PATH` 覆盖
- MCP 教师数据范围同样受 `TEMPORARY_GLOBAL_TEACHER_ACCESS` 控制，默认开启全局访问；设置为 `0` 后按课程成员关系过滤。连接含学生成绩和作业信息的数据前应先确认客户端、账户及部署环境的访问边界

## 常见问题

| 现象 | 处理 |
|------|------|
| 批改全部失败 | 检查 AI 设置与额度；日志中看 `HTTP 402` / `429` / `请求失败` |
| 提示模型不支持图片 | 换用支持图片输入的多模态模型；纯文本模型无法读取扫描件 |
| 批阅按钮是灰的 | 还没上传教师版答案，或还没勾选并保存作业范围 |
| 批阅超时（5 分钟） | 模型卡住或题量过大；换更快的视觉模型，或压缩 PDF 页数后重试 |
| 输出被截断 | 模型输出上限太小或题量过多；调大输出上限或减少一次批阅的页数 |
| 题目漏判 | 模型未返回的题不会凭空补；可在复核页手动补充，或重试批阅 |
| 批改很慢 | 整份 PDF 一次请求，页数越多越慢；可压缩 PDF 后重试 |
| 学生看不到批改结果 | 复核完成只在教师端可见；到报告页确认报告已生成，再点「一键发布给学生」 |
| 学生看不到讲义 | 该讲次还没上传学生版讲义 PDF，到讲次页补传 |
