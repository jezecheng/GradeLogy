# 教师端界面设计与实施顺序（历史方案记录）

本文记录 2026-11-18 的教师端设计方案和验收口径，不是当前 UI 的逐项说明，文中 commit 和未完成项也不是当前状态。实际流程以当前 [老师手册](teacher.md)、[教师流程与前置条件](teacher-workflows.md) 和代码为准；当前 UI 行为变化后不要仅依赖本历史方案判断。

## 设计方向

按教师的任务顺序组织：找到待办→批阅→复核→公开→教学分析。低频配置保留明确入口，避免挤占日常任务的首屏。

| 页面 | 默认内容 | 次级内容 |
| --- | --- | --- |
| 我的课程 | 课程与待批阅/待复核摘要；标题旁创建按钮 | 卡片更多菜单中的编辑/删除 |
| 课程 | 讲次、学生、考试分区；讲次默认打开 | 课程设置：协作、提示词、图谱关联、备份 |
| 讲次 | 提交与批阅状态、准备摘要 | 已完成的答案上传和范围设置；分析及费用详情 |
| 复核 | 首个未复核题、题目导航、进度和保存状态 | 已复核题、原页与报告生成入口 |
| 图谱 | 搜索、分类、图与所选概念详情 | 资料、治理、协作、存储明细 |
| 提示词 | 用途筛选、列表、按条展开编辑及明确引用课程 | 系统模板与占位符说明；版本历史待实现 |
| AI 设置 | 当前有效连接与模型、连接编辑、常用设置 | 高级输出上限、价目、演示模式 |

未完成、失败或待确认的事项显示可见摘要；必要时展开对应区块。轮询和窗口变化不能自动改变教师的阅读位置或丢失编辑内容。

## 适配与操作规则

- 手机小于 768px：单列，主要触摸目标至少 44×44px；表单至少 16px。复核以单题为单位，作答与答案可切换，原页独立查看。图谱优先搜索/分类入口，详情用卡片或底部抽屉。
- 768–1199px：按可用空间使用单列或对照双列，不强行显示图、详情和导航三列。
- 1200px 以上：普通页面保持适当行宽，批阅和图谱使用更宽工作区；1600px 以上可增加可调分栏。配置表单不随屏幕无限拉宽。
- 对照信息横向并列，连续步骤按执行顺序组织；手机宽表局部滚动，身份、状态和主操作优先可见。
- 主按钮文案准确表达后果：全部复核后完成复核并生成/重新生成报告；学生公开只能在报告页一键执行，同时公开报告与逐题结果。任务入口在空队列时也保留历史访问。
- 助手、通知与固定保存条不得遮挡输入和审核按钮；软键盘、安全区、200% 缩放、键盘导航和减少动画设置纳入验收。

## 实施顺序

1. 建立共用间距、字号、按钮、状态、导航和抽屉规则；重排课程与讲次，修正复核发布文案。
2. 完成批阅工作区，增加待复核定位和保存反馈，保持现有权限与发布规则。
3. 图谱浏览分区、搜索/详情，再改提示词与 AI 设置编辑体验。
4. 完成任务持久化、事务与图谱版本底座，再做教师确认的诊断、复习和复测闭环。

每步同步角色手册和相关模块文档；行为变化用必要回归测试验证，布局用真实内容及浏览器尺寸检查。当前无需引入前端框架。

## Roadmap 状态口径

用“已实现、部分实现、未发现实现、已调整范围”，分别说明业务、界面与工程可靠性。不要把 JSON 迁移当作 GraphML，把增量合并当作资料版本重建，把 AI 文字建议当作可跟踪复习计划，或把备份可用当作在线恢复全面原子化。

当前 P1–P5 均为部分实现；分批原卷批阅、Excel 成绩导出、覆盖热力图、完整图谱差异历史和发布自动回滚仍待实现。具体依据和每阶段验收见评估报告。

## 本轮实现边界

布局与交互无需新增前端框架或生产依赖。分区切换保留表单内容，折叠和分区状态按账号与页面保存于当前浏览器会话。图谱搜索复用全量节点请求，限制显示 40 项；大图数据传输仍待优化。单题自动保存按题串行，提交前等待保存完成，失败阻止跳转。

保存草稿撤回逐题结果与报告的公开状态；全部复核且没有批阅任务时才能生成报告。报告预览不会自动公开草稿；报告页的唯一发布入口同时控制报告、逐题结果与学生错题/薄弱点。

任务租约、业务事务统一、图谱修订历史与可追踪复习计划尚未实现，不计入本轮 UI 完成范围。
