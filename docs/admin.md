# 管理员手册

管理员负责账号、系统数据与运维，不参与具体课程与批改。

## 登录

- 入口：`/login`，默认账号 `admin / admin123`
- 首次登录（或密码被重置为默认值）会强制跳转改密页，改完才能进入其他页面
- 右上角显示当前账号与角色，可改密或退出

## 用户管理

入口：导航栏「用户管理」（`/admin/users`）。

| 操作 | 说明 |
|------|------|
| 创建账号 | 填写用户名（登录名，唯一）、姓名、角色、初始密码；密码留空则为 `123456` |
| 学生附加信息 | 创建学生时可选填「真实姓名」「学籍号」；学籍号 1-32 位字母、数字或 `_.-`，仅用于识别，不参与登录 |
| 初始密码 | 使用默认密码的账号，首次登录必须修改 |
| 重置密码 | 可指定新密码；重置为默认密码时同样要求首次登录修改 |
| 删除账号 | 不可删除当前登录的自己 |

> 删除不可恢复：删除老师会级联删除其课程、作业、学生提交与教案；删除学生会删除其选课关系与全部提交。批量调整前建议先导出备份。

## 系统维护

入口：导航栏「系统维护」（`/admin/consistency`）。

### 数据概览

显示账号、课程、作业、提交、逐题记录的条数，以及当前数据目录与数据库路径，便于确认部署环境。

### 导出全部数据

点击「导出全部数据」下载 zip，内容包括：

- `data.sqlite`：SQLite 在线备份 API 生成的一致快照（可不停服）
- `uploads/`：学生原件与教师版 PDF
- `manifest.json`：导出时间、版本与文件计数

不包含：`logs/`、`backups/`、`.secret_key`。备份含 AI Key 与密码哈希，请按机密文件保管。

### 自动备份

系统每 30 分钟检查一次，当天还没有备份就自动生成一份完整备份（与导出的 zip 内容一致），存放在 `<数据目录>/backups/`，命名 `gradelogy_YYYYMMDD_HHMMSS.zip`。

- 保留最近 `BACKUP_KEEP` 份（默认 7），超出的自动删除；恢复前的 `pre_restore_*` 快照不受影响
- 「立即备份」按钮可随时额外生成一份，列表里可直接下载（仅管理员可访问）
- 相关环境变量：`BACKUP_DIR`（默认 `$DATA_DIR/backups`）、`BACKUP_KEEP`、`AUTO_BACKUP=0` 可关闭
- 多进程部署（如 gunicorn 多 worker）时用 `backups/.auto.lock` 文件锁保证只有一个进程在备份；容器部署请确保该目录可写且不被只读挂载

### 从备份恢复

上传之前导出的 zip：

1. 校验压缩包内容（拒绝越界路径）、解压总量（`MAX_RESTORE_MB`，默认 2048MB）、数据库表结构与 `PRAGMA integrity_check`
2. 自动把当前数据备份到 `<数据目录>/backups/`（`pre_restore_*.sqlite` 与 `uploads_*`）
3. 覆盖附件与数据库，清空会话，要求重新登录
4. 恢复后自动执行一次数据库迁移，**旧版本导出的备份也能恢复到新版本**

### 一致性检查

比对数据库记录与磁盘文件，报告：

| 问题 | 是否可自动修复 |
|------|----------------|
| 孤儿题目（提交已删除但逐题记录还在） | 是 |
| 提交扫描件丢失 | 否，仅报告 |
| 作业答案 PDF 丢失 | 否，仅报告 |

「执行安全修复」只清理孤儿记录，不会删除任何文件，避免误删数据。

## 数据备份与迁移

完整备份 = **数据库 + 附件目录**，两者必须成对保存：

| 内容 | 默认位置 | 说明 |
|------|----------|------|
| 数据库 | `<数据目录>/data.sqlite`（含 `-wal` / `-shm`） | 账号、课程、作业、提交、逐题记录、AI 设置 |
| 附件 | `<数据目录>/uploads/` | 学生原件与教师版 PDF |
| 备份 | `<数据目录>/backups/` | 每日自动备份与恢复前快照；迁移时可一并带走 |
| 密钥（可选） | `<数据目录>/.secret_key` | 不备份也可以，新系统重新生成，仅导致重新登录 |

### 方式一：页面导出 → 新机器恢复（推荐）

1. 旧机器：「系统维护」→「导出全部数据」，得到 `gradelogy_<时间>.zip`
2. 新机器：按 README「快速开始」或「Docker 部署」启动干净实例
3. 用 `admin / admin123` 登录并修改初始密码
4. 「系统维护」→「从备份恢复」，上传 zip
5. 恢复后重新登录（用备份里的原账号），执行一次「一致性检查」，访问 `/healthz` 应为 200

Docker 部署时数据目录是挂载卷 `./data`，无需额外准备。

### 方式二：直接拷贝数据目录（同版本、可停机）

```bash
# 停服务后，整个目录一起拷贝（数据库与附件必须同源）
rsync -av data/ /srv/gradelogy/data/

# 新机器启动时指向该目录
DATA_DIR=/srv/gradelogy/data python app.py
```

无法停机时请改用页面导出（在线快照）。

### 方式三：手动落盘恢复（页面进不去时兜底）

1. 停服务
2. 解压备份：`unzip gradelogy_<时间>.zip -d /tmp/restore`
3. 把当前 `data.sqlite` 与 `uploads/` 移到别处
4. 将 `/tmp/restore/` 中的 `data.sqlite` 与 `uploads/` 放回数据目录
5. 启动服务，启动时自动迁移

### 注意事项

- 恢复是**覆盖**，不是合并；覆盖前系统会自动留一份 `backups/`
- 备份包含敏感信息（AI Key、密码哈希）
- 只支持旧版本 → 新版本；**不支持降级**
- 超过 2048MB 的备份需调大 `MAX_RESTORE_MB`；前面有 Nginx 时同时调大 `client_max_body_size`
- `.secret_key` 不在备份包内，恢复后所有人需要重新登录

## 日志与排查

日志位于 `<数据目录>/logs/app.log`，5MB 轮转、保留 5 份；`LOG_LEVEL` 控制级别（设为 `WARNING` 可关闭访问日志）。记录内容：

- 访问日志：方法、路径、状态码、耗时、账号、来源 IP；健康检查与静态资源不记录
- 审计：登录成功/失败、建号、重置密码、删号、改密
- AI 调用：模型、耗时、`finish_reason`；429 限流、请求失败、输出被截断会记 warning
- 批改：开始（提交/作业/学生）、完成（题数）、失败原因；单次批阅超时 300 秒且不重试，超时会记为 `AI 请求异常`
- 安全事件：CSRF 校验失败、越权访问文件或修改他人数据

常见排查：

| 现象 | 先看什么 |
|------|----------|
| 批改全部失败 | `AI 请求失败` / `HTTP 402`（额度）/ `HTTP 429`（限流） |
| AI 返回空 | `AI 输出被截断`（调大 `max_tokens`）或模型不支持图片 |
| 批阅卡满 5 分钟才报错 | 模型把额度耗在思考上或输入图片过多；换更快的视觉模型，或降低渲染分辨率 |
| 恢复失败 | `备份数据库不可用` 或 `恢复失败` 后的堆栈 |
| 页面偶发 500 | 对应请求前后的异常堆栈 |

## 管理员密码丢失

优先让另一个管理员账号重置。若没有其他管理员，在服务器上生成哈希并直接改库：

```bash
python - <<'PY'
from werkzeug.security import generate_password_hash
print(generate_password_hash("你的新密码"))
PY

sqlite3 data.sqlite \
  "UPDATE users SET password_hash='<上一步输出的哈希>', must_change_password=1 WHERE username='admin';"
```

Docker 部署时在容器内执行，数据库路径为 `/data/data.sqlite`：

```bash
docker compose exec gradelogy python -c \
  "from werkzeug.security import generate_password_hash; print(generate_password_hash('你的新密码'))"
```
