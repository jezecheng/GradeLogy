# UX 改进计划

依据 2026-11-22 的独立 UX 评审整理。本计划用于后续 Codex 实施；评审依据本地手册和模板源码，没有通过浏览器复现。实现前应重新核对当前代码与交互，遇到与基线不一致时以当前代码为准。

## 目标

- 缩短教师建课、加学生、准备批阅和发布结果的操作路径。
- 让学生更快发现近期需要提交的作业，并明确考试成绩的状态。
- 保持课程、学生文件与成绩的现有权限隔离，不因交互简化扩大可见范围。
- 将无操作自动登出窗口调整到 30–60 分钟，并在登出前提供可操作的倒计时提醒。
- 避免自动触发额外 AI 请求；AI 操作仍由用户明确发起，并保留现有后台任务状态。
- 同步更新老师、学生和管理员手册，保证页面文案与实际行为一致。

## 生产流程复现依据

此前在生产 QA 数据上完成过一次基于登录会话的流程与权限检查。它验证了服务端流程和权限结果，但不是浏览器视觉复现；后续浏览器走查应补记页面标签、交互反馈和截图位置。

| 已走流程 | 已确认结果 | 对本计划的作用 |
|---|---|---|
| 管理员建 1 名 QA 老师、2 名 QA 学生；搜索/角色筛选；重复用户名；停用与登录 | 建号、筛选成功；重复账号被拒绝；停用账号不能登录 | UX-01 在现有逐个加课之后补批量加课；不可绕过启用状态检查 |
| QA 老师建课程、加入两名学生、建讲次/考试、录入两人成绩 | 服务端流程成功 | 为 UX-01、UX-04、UX-05 提供主线验收场景 |
| 两名学生查看成绩与提交；另一学生尝试读取对方文件 | 学生各自只看到自己的成绩；跨学生文件访问返回拒绝 | UX-02、UX-03、UX-05 的隐私/权限验收必须使用两名学生 |
| 非课程老师访问 QA 课程、讲次和上传文件 | 均被拒绝 | 批量选课、状态面板和文件链接改动必须保留课程成员校验 |
| 老师端 AI 连通性 | 一次最小请求成功 | 后续 UX 改造不应自动重发连接/题目分析/批阅请求 |

QA 数据按测试约定保留记录，测试账号目前停用。浏览器视觉走查仍需覆盖页面实际布局、提示文案和手机尺寸；不能仅凭上述 HTTP/权限结果判断视觉交互已验收。

## 优先级与阶段

### 阶段 0：确认发布与成绩状态规则

在改动 UI 或数据库前先核实当前发布行为，并作出以下产品决策：

1. 逐题结果与批改报告是否继续独立发布。现有设计文档要求分别公开；评审建议提供合并入口。建议保留独立状态与独立权限门槛，在状态面板同时呈现两者，并允许教师显式选择一次发布一个或两个对象。不要因 UI 整合而自动公开报告或逐题结果。
2. 考试“已录入”“缺考”“已发布”如何定义。建议把缺考设为教师可明确选择的状态；保留当前已保存分数即时对学生可见的行为，除非另行决定加入草稿/发布步骤。
3. 为既有考试记录制定迁移映射。已保存的分数或评语应保持现有可见性；没有成绩记录的学生应显示为待录入，不得默认为缺考。
4. 明确会话限制是“连续无操作时长”还是“从登录开始的绝对时长”。本计划按连续无操作时长处理，建议 45 分钟；若产品要求绝对时长，应另定活跃会话续期规则。

**阶段验收**：在实现前将上述规则写入页面状态表和对应手册；明确历史记录如何映射；教师能区分逐题结果发布状态与报告发布状态。

### 阶段 1：降低高影响操作的摩擦与误操作风险

#### UX-07 会话空闲超时与登出提醒（高）

**现状依据**：当前服务端配置为 8 小时会话寿命，并在每个请求时刷新会话有效期（PERMANENT_SESSION_LIFETIME=8h、SESSION_REFRESH_EACH_REQUEST=True）。因此只改浏览器计时器不足以实现空闲超时：后台轮询或定时请求可能持续刷新会话。

**问题**：长时间离开设备时会话仍保持有效；用户也没有在失效前处理未保存内容的提示。

**计划**：将连续无操作期限设为 **45 分钟**（落在 30–60 分钟范围内）；无操作 **40 分钟**时弹出模态提醒，显示 5 分钟倒计时和“继续使用”“退出登录”两个明确操作。继续使用必须向服务端确认会话仍有效并刷新期限；倒计时结束后清除本地登录态并跳转登录页。区分用户主动操作和后台轮询：日志尾读、状态轮询、静态资源或其他定时请求不能单独续期。

**实现要点**：

- 服务端会话验证是最终依据；客户端计时器负责提醒，不能单独作为访问控制。
- 采用真正的空闲活动时间，而非“最后一个任意 HTTP 请求”。核对 Flask 会话刷新配置及管理员日志页等后台轮询，避免无人在场时仍保持会话。
- 跨标签页共享活动与登出状态；一个标签页主动续期后，其他标签页同步更新倒计时。任一标签页退出或会话失效时，其他标签页下一次操作也应回到登录。
- 页面处于后台、电脑休眠或网络断开时，恢复后先验证会话再继续操作；不能因 JS 定时器暂停而无限延长会话。
- 弹窗提示未保存表单/复核内容。倒计时到期时不得静默提交；对可恢复草稿采用现有本地暂存策略，其他表单提示需重新登录后重试。
- 所有角色统一超时规则；管理员、老师和学生不因页面后台轮询而有不同有效期。

**验收标准**：

- 配置与行为体现 45 分钟空闲期限，40 分钟出现提醒，倒计时到 0 后登出。
- 用户主动继续使用时，服务端确认会话有效并刷新 45 分钟期限；过期后点击继续不能复活旧会话。
- 只有可验证的用户活动能够刷新空闲期限；后台轮询不能续期。
- 多标签页、浏览器休眠/恢复、网络中断/恢复后状态一致，不出现已登出页仍可访问受限数据的情况。
- 提醒可用键盘操作，焦点进入弹窗；显示剩余时间，两个操作分别续期和立即登出。
- 登出后所有受限路由仍返回登录页；无需等待下一次整页导航才发现会话失效。

**重点回归**：40 分钟提醒、45 分钟到期、主动活动重置、被动日志轮询不重置、后台标签页、多个标签页续期/登出、休眠恢复、过期后提交表单、键盘及移动端弹窗。

#### UX-01 批量加入课程学生（高）

**问题**：管理员可批量建账号，但教师需要回课程页逐个加入学生，大班名单操作繁琐。

**计划**：在课程“学生”分区增加多选与批量加入入口；支持按姓名或用户名搜索。加入前显示待加入名单、已在课程中的账号、停用账号或无效账号及最终人数；确认后显示成功、跳过和失败数量。

**验收标准**：

- 教师可一次选择多个启用且尚未加入课程的学生。
- 重复成员不会被重复添加；停用账号不能加入。
- 确认前可检查名单与数量；提交后能辨认成功、跳过和失败项。
- 只影响当前课程的选课关系；既有成绩、提交和其他课程关系不变。
- 共同管理教师的课程范围与课程创建者规则保持一致。

**重点回归**：空选择、全是重复成员、混合有效/无效账号、非本课程教师直接请求、课程中已有成绩/提交的学生。

#### UX-02 复核与报告发布状态面板（高）

**问题**：逐题结果与报告分成不同页面和动作，可能出现逐题结果已公开而报告仍未发布的状态。

**计划**：在讲次/复核/报告入口统一显示：批阅状态、逐题复核进度、逐题结果是否公开、报告是否已生成及是否公开。按当前设计文档保留明确的“完成复核并公开逐题结果”操作和独立报告发布入口；可评估增加显式的合并发布选项，但不得将其设为自动行为。

**验收标准**：

- 教师无需进入多个页面即可看清两种发布状态和下一步。
- 未完成逐题复核、仍有批阅任务、没有报告内容时，相关发布动作被阻止并说明原因。
- 合并发布（若实现）在提交前列明将公开的对象，并要求教师明确选择。
- 学生在逐题结果未公开时看不到逐题详情；报告未公开时无法访问报告 URL。
- 撤回逐题结果或报告时，教师端状态即时更新，学生端相应内容不可访问。

**重点回归**：未复核、任务进行中、草稿保存、报告已生成但未发布、分别发布、合并发布、撤回、学生直接访问未发布报告。

### 阶段 2：优化学生任务发现与教师准备流程

#### UX-03 学生近期截止与逾期列表（中）

**问题**：学生首页按课程折叠讲次，截止时间在课程内才可见，待交任务可能不显眼。

**计划**：在“我的学习”顶部增加跨课程近期截止/逾期区块，按截止时间排序；显示课程、讲次、截止时间、提交状态，并链接到对应讲次。无截止时间的讲次不进入截止排序，但仍保留在课程分组中。

**验收标准**：

- 只显示当前学生已加入课程中的讲次，不返回其他学生或课程成员的数据。
- 已提交、逾期、即将截止和无截止时间状态有清晰区分；重复提交状态按现有“最新提交为准”规则展示。
- 按用户设置的显示时区格式化截止时间；日期边界不会造成误标。
- 空状态说明当前没有近期截止任务，并保留课程列表入口。
- 手机屏幕下关键信息和“去提交”操作无需横向滚动即可访问。

**重点回归**：多课程排序、未提交/已提交/已批改、逾期、即将截止、无截止日期、时区切换、空课程列表。

#### UX-04 讲次批阅准备清单（中）

**问题**：教师需依次上传教师版答案、选择页码、生成题目清单、选择本次作业题目；创建讲次时两份 PDF 又标为可选，前置条件容易被忽略。

**计划**：将现有摘要和折叠区整理为可逐项完成的准备清单：标准答案、答案页范围、题目清单、布置题目。学生版讲义作为单独的学生资源项显示。将“全不选并保存＝使用整份教师版 PDF”的隐含行为改成可读的明确选项。

**验收标准**：

- 每一步显示未开始、进行中、已完成或失败，并说明对 AI 批阅的影响。
- 上传、解析或题目生成失败时保留已有选择并提供明确重试入口。
- 保存作业范围不会自动重复触发 AI；知识点标签生成仍为单独、可观察的任务。
- 未满足批阅前置条件时，主操作解释缺少哪一步并链接到对应区域。
- 已完成设置不会因展开/折叠、刷新或分区切换而丢失。

**重点回归**：无答案、答案上传、全 PDF 范围、部分页范围、无题目清单、未选题、生成失败、AI 设置缺失、任务排队状态。

### 阶段 3：明确考试状态与登录帮助

#### UX-05 区分待录入、缺考与已发布成绩（中）

**问题**：教师端留空可表示未参加或尚未录入，学生端两种情形都显示“未公布”。

**计划**：在阶段 0 决策后，为成绩行增加明确状态和教师操作。若继续即时发布，状态至少区分“待录入”“缺考”“已发布”；若加入草稿状态，应单独定义保存与发布动作。更新成绩表单和学生成绩页的状态标签及说明。

**验收标准**：

- 教师可区分尚未处理、缺考和有成绩的学生。
- 学生只看到本人被允许查看的状态和成绩，不暴露其他学生成绩。
- 历史分数与评语按阶段 0 映射后保持原有可见性。
- 数据库迁移可重复执行，不丢失分数、评语或更新时间。
- 空分数不能被误判为零分；缺考不能被统计成零分，除非现有统计规则明确要求并已记录。

**重点回归**：新考试、历史考试迁移、成绩保存/清除、缺考、评语无分数、学生视图、教师共同管理课程。

#### UX-06 登录页角色与帮助信息（中）

**问题**：登录页提示教师使用管理员分配账号，但未解释学生是否使用同一入口、账号取得方式与密码问题的处理路径。

**计划**：说明老师、学生和管理员共用此登录入口；简要说明账号发放方式、用户名格式和忘记密码联系渠道。提供公开可见的简短使用说明，避免要求用户先登录才能找到登录帮助。

**验收标准**：

- 不同角色均能确认是否使用当前登录页及账号从何处取得。
- 忘记密码提示具体说明联系对象；不展示或泄露账号、密码或存在性信息。
- 帮助内容可键盘访问，移动端布局清晰；登录表单行为不变。

**重点回归**：登录成功/失败提示、键盘顺序、移动端窄屏、公开帮助链接可访问性。

## 共通实施要求

- 遵循 [教师端界面设计与实施顺序](ui-design.md) 的导航、状态、手机触控、发布文案和无前端框架方向。
- 每个阶段独立提交并更新对应手册：批量加课更新管理员/老师手册；截止列表与考试状态更新学生手册；批阅发布更新老师/学生手册；登录帮助同步所有角色说明。
- 表单写操作保留 CSRF；后端继续按角色、课程成员关系和学生归属检查，不把前端隐藏按钮当作权限控制。
- 会话期限以后端校验为准；不能让 AI 队列、日志轮询、静态资源或前端倒计时替代登录鉴权。
- 任何新发布状态都必须在后端阻止未授权读取，而不只是隐藏页面链接。
- 对学生成绩、文件和发布状态使用合成数据验收；测试不得调用真实学生数据或无意触发 AI 请求。
- 保持桌面与手机布局、键盘操作、焦点顺序、错误提示和空状态一致。

## 推荐交付顺序

1. 先完成阶段 0 的状态定义与迁移方案。
2. 优先实现 UX-07 会话超时与提醒；通过过期、后台轮询和多标签回归后，再并行实现 UX-01 批量加课与 UX-02 发布状态面板。
3. 实现 UX-04 批阅准备清单和 UX-03 学生截止列表。
4. 实现 UX-05 考试状态（含迁移）与 UX-06 登录帮助。
5. 每阶段完成后更新手册、执行对应回归检查，并在交付说明中列出行为变化、迁移结果和未覆盖项。

## 验收完成定义

- 所有验收标准均可通过角色化流程复现。
- 管理员、课程创建者、共同管理教师、学生之间的数据边界未被扩大。
- 逐题结果和报告的发布门槛在后端有效，历史记录迁移保持既有可见性。
- 相关手册和页面状态文案一致，桌面/手机均可完成主任务。
- 计划中的每个条目标记为已完成、已调整范围或未实施，并附原因。
