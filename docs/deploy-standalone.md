# 单机简易部署指南（Windows / macOS）

这份指南面向 **没有技术背景、只想把系统运行在自己电脑上** 的使用者。

你不需要安装 Python、不需要安装 Git，也不需要购买云服务器。只需安装 Docker Desktop、下载项目压缩包，再复制一条命令。

## 先确认这种方案适合你

适合：

- 主要在这台电脑上使用，或在同一个家里 / 办公室 Wi-Fi 内使用
- 使用期间可以保持电脑开机、不休眠
- 希望数据保存在自己的电脑上

不适合：

- 学生需要在校外、4G/5G 或其他网络随时访问
- 希望电脑关机后系统仍能使用
- 需要 HTTPS、公网访问或自动发布更新

这些情况请使用 [腾讯云部署与自动发布](deploy-tencent.md)。

## 一、准备电脑

建议：

- Windows 10 / 11 64 位，或 macOS
- 可用内存 8 GB 或以上
- 磁盘至少预留 10 GB；学生 PDF 较多时需要更多空间
- 安装和首次构建期间保持网络畅通

AI 批阅在你配置的模型服务商服务器上运行，本机主要负责网页、文件存储和 PDF 转图片。

## 二、安装 Docker Desktop

Docker Desktop 是让系统运行起来的基础软件，只需安装一次。

1. 打开官方下载页面：<https://www.docker.com/products/docker-desktop/>
2. 下载并安装：
   - **Windows**：选择 Windows 版本；安装过程中如果出现 WSL 2 相关选项，保持默认并允许安装
   - **Mac**：Apple 芯片选择 Apple Silicon，较老的 Intel Mac 选择 Intel Chip
3. 按提示重启电脑（如果安装程序要求）。
4. 打开 Docker Desktop，等待左下角或状态栏显示已经运行。

以后使用 GradeLogy 时，Docker Desktop 也需要保持运行。

## 三、下载并解压项目

1. 打开项目的 GitHub 页面。
2. 点击绿色 **Code** 按钮。
3. 点击 **Download ZIP**。
4. 解压下载的 ZIP。

解压后应看到一个文件夹，里面直接包含：

```text
app.py
docker-compose.yml
Dockerfile
templates
...
```

如果打开后只看到另一层同名文件夹，请继续进入最里面这一层。后文把这个文件夹称为“项目文件夹”。

> 请把项目文件夹放在自己能找到的位置，例如“文档”目录。不要放在临时下载目录，也不要在系统运行后随意移动或重命名它。

## 四、第一次启动

### Windows

1. 打开解压后的项目文件夹。
2. 在文件夹空白处点击右键，选择 **在终端中打开**。
   - 如果没有这个选项，可以在文件资源管理器地址栏输入 `powershell` 并按回车。
3. 在打开的窗口中输入下面这条命令，然后按回车：

```bash
docker compose up -d --build
```

### macOS

1. 打开“启动台”→“其他”→“终端”。
2. 输入 `cd `（`cd` 后面有一个空格），先不要按回车。
3. 把解压后的项目文件夹拖进终端窗口，再按回车。
4. 输入下面这条命令，然后按回车：

```bash
docker compose up -d --build
```

### 等待启动完成

第一次运行需要下载和构建运行环境。请保持 Docker Desktop 开启，直到命令执行完毕、窗口重新出现可输入状态。

然后打开浏览器，访问：

```text
http://127.0.0.1:5000/login
```

首次管理员账号：

```text
用户名：admin
密码：admin123
```

登录后系统会要求修改密码，请设置一个只用于本系统的新密码。

`127.0.0.1` 表示“当前这台电脑”，所以只有本机可以使用这个地址。

## 五、日常使用

### 每次打开电脑后

1. 打开 Docker Desktop。
2. 等待它启动完成。
3. 如果网页没有自动恢复，打开 Docker Desktop 的 **Containers**，找到 `gradelogy` 并点击启动。
4. 打开 <http://127.0.0.1:5000/login>。

可以在 Docker Desktop 的设置中开启“登录电脑时自动启动 Docker Desktop”。

### 暂时不用时

可以直接关闭浏览器。需要彻底停止系统时，在 Docker Desktop 的 **Containers** 中停止 `gradelogy` 即可。

也可以在项目文件夹的终端中运行：

```bash
docker compose stop
```

下次启动：

```bash
docker compose start
```

**不要删除项目文件夹中的 `data` 文件夹。** 里面保存着账号、成绩、AI 设置和学生上传的文件。

## 六、让同一 Wi-Fi 下的其他电脑或手机访问

可选步骤，不需要局域网访问时可以跳过。

1. 先确认本机访问正常。
2. 查询本机局域网 IP：
   - Windows：在终端运行 `ipconfig`，找到当前网卡的 `IPv4 地址`，例如 `192.168.1.20`
   - macOS：在“系统设置”→“Wi-Fi”→当前网络的“详细信息”中查看 IP 地址
3. 其他设备连接同一个 Wi-Fi，在浏览器访问：

```text
http://192.168.1.20:5000/login
```

把示例 IP 换成你刚查到的地址。

如果只有其他设备打不开：

- 检查本机是否休眠、Docker Desktop 是否运行
- 检查两台设备是否连接同一个 Wi-Fi
- Windows 弹出防火墙提示时，只允许在“专用网络”中访问，不要勾选公用网络

局域网地址可能因路由器重新分配而变化。此方式不是公网访问，不要在路由器上把 5000 端口映射到互联网。

## 七、配置 AI 批阅

1. 使用老师账号登录。
2. 打开顶部 **AI 设置**。
3. 按所用服务商的信息填写 API 地址、API Key 和模型名称。
4. 保存后先做一份小作业测试，再批量使用。

AI Key 相当于密码，不要截图分享或提交到 GitHub。局域网 HTTP 也不是加密连接，请只在可信网络中使用。

## 八、备份：最重要的一步

### 推荐：网页导出备份

1. 使用管理员账号登录。
2. 打开 **系统维护**。
3. 点击 **导出全部数据**。
4. 把下载的 ZIP 保存到移动硬盘、U 盘或其他安全位置。

建议定期导出，尤其是在大量录入成绩或上传作业之后。

### 手动备份

1. 在 Docker Desktop 中停止 `gradelogy`。
2. 复制项目文件夹里的整个 `data` 文件夹到其他位置。
3. 复制完成后重新启动 `gradelogy`。

备份包含学生资料、密码哈希和 AI 配置，请像保管成绩单一样妥善保管，不要上传到公共网盘或群聊。

## 九、以后如何升级

升级前一定要备份。ZIP 部署不会自动更新。

1. 在网页中导出一份完整备份。
2. 在旧项目文件夹的终端中依次运行：

```bash
docker compose stop
docker compose rm -f
```

第二条命令只移除旧容器，**不会删除项目文件夹里的 `data`**。如果你不确定，也可以改用 Docker Desktop 的 Containers 页面停止并删除 `gradelogy` 容器，但不要删除任何数据目录或备份。

3. 下载并解压新版本到一个**新的文件夹**，暂时保留旧文件夹。
4. 把旧项目文件夹中的 `data` 整个复制到新项目文件夹中。
5. 如果旧项目文件夹中存在 `.env`，也一起复制；没有则忽略。
6. 在新项目文件夹中打开终端，运行：

```bash
docker compose up -d --build
```

7. 打开网页，确认账号、课程、作业和成绩都在。
8. 确认无误前，不要删除旧项目文件夹和备份 ZIP。

ZIP 中没有 Git 提交记录，因此页面只显示 `VERSION` 的版本号，没有提交哈希后缀和提交时间，这是正常现象。

## 十、遇到问题怎么办

### 提示 `docker` 不是命令、找不到命令

- 确认 Docker Desktop 已安装并打开。
- 关闭当前终端，再重新打开一个终端。
- 仍不行时重启电脑后再试。

### 提示无法连接 Docker、Docker Engine 不可用

先打开 Docker Desktop，等它完全启动后再运行命令。

### 浏览器打不开网页

在项目文件夹的终端中运行：

```bash
docker compose ps
docker compose logs --tail=100
```

把两条命令的完整输出保存下来，交给项目维护者排查。日志如包含 API Key、学生姓名等信息，发送前请先遮盖。

### 提示 5000 端口被占用

通常是旧实例仍在运行。先在 Docker Desktop 中停止旧的 `gradelogy`，再启动新实例。

### 忘记管理员密码或需要迁移整台电脑

参见 [管理员手册 · 数据备份与迁移](admin.md#数据备份与迁移)。恢复备份前，先保存当前数据，避免把新数据覆盖。
